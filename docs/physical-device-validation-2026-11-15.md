# 実機で行う総合検証の候補

2026-11-15の追加依頼に基づく、実施前の検証台帳。検証用Googleアカウント・専用グループを使う。既存の個人予定・普段の共有グループを検査データに流用しない。

これは候補と合格条件の一覧であり、実機での合格記録ではない。自動検査・Cloud Emulator・シミュレーターの通過を実機の通過に数えない。以下のケースは、実施結果を別途記録するまで全件「未実施」とする。

候補は216項目、うち最適化20項目。[ID付きJSONL台帳](qa-assets/physical-2026-11-15/cases.jsonl)も同じ内容で用意した。1行を1ケースとし、実施結果・証拠を追加して追跡する。

## 実施順と記録

1. 最終ソース・インストール済みバンドル・接続先・配備済みRules／API／ワーカーの版を固定する。
2. 検証用アカウントA・B、専用Googleカレンダー、専用Tasksリスト、専用共有グループを用意し、送信・受信先を確認する。
3. 実機Aで個人・Google連携を確認し、相手端末Bで同一アカウント同期と別アカウント共有を確認する。Bは既存シミュレーターを再利用できる。iOS／Android間の実機確認はAndroid実機が用意できた場合に別の結果として記録する。
4. 通常利用、再認証、通信断、競合、終了・再開、受領・復旧の順に進める。データ破壊や本番設定変更を前提にした試験を通常利用へ混ぜない。
5. 通信と性能は操作前後の差分を測り、改善後も同じケースで内容の到着と保存結果を再照合する。

各ケースには、ID、開始・終了時刻、アプリ／OS／サーバーの版、アカウントの仮名、端末A・B、条件、操作、期待結果、観測結果、証拠ファイル、通信数・バイト数、所要時間、後片付けを記録する。結果は「未実施／実施中／通過／不具合／環境待ち／明示保留」を区別する。失敗後に直した場合も最初の失敗と再検証を残す。

試験用の名前は `LFQA-実施日-ケースID` に統一する。検証用データの削除・解除もケースIDに限定し、予定名の部分一致だけで既存データを消さない。資格情報、メールアドレス、招待URL、トークン、署名鍵、PDF本文、個人予定の本文は公開証跡へ記録しない。

2026-11-16の利用者の追加指示により、検証データは片付けず残す。後片付けだけを目的とした削除・解除は行わない。削除動作そのものを検証した結果と、データの片付けは区別して記録する。指示の意味を確認する前に行ってしまった検証予定2系列の削除は、実施済みの結果として残す。

実施結果は[結果台帳](qa-assets/physical-2026-11-15/results.jsonl)へ候補ID・条件別に追記する。1つの条件の通過を、その候補の全条件や216件全体の通過として数えない。[繰り返し予定の実機照合](qa-assets/physical-2026-11-15/shared-recurrence-2026-11-16.json)には、個別変更・今後・全体・分割境界・取消保持を区別して記録した。

## 状態の組み合わせ

全組み合わせを無差別に掛け合わせず、単独条件を網羅した上で、境界をまたぐ組み合わせを重点的に重ねる。同じケースでも次の条件が違えば別の実施結果とする。

| 軸 | 対象にする状態 |
| --- | --- |
| アカウント | 未接続、A接続、再認証、A→B切替、ログアウト、認可取消、途中キャンセル |
| Google機能 | 個人予定、共有予定のGoogle表示、本人端末間の空き時間、個人Tasks、共有Tasksの各ON／OFF。各単独、全ON、全OFF、Calendarのみ、Tasksのみ、共有ありの代表組み合わせ |
| グループ | なし、作成直後、参加待ち、所有者、編集可、申請のみ、読み取りのみ、除名、退出、再参加 |
| ネットワーク | 通常、低速、完全オフライン、保存中に切断、応答だけ紛失、再接続、バックグラウンドから復帰 |
| 保存内容 | 空、単発、繰り返し、個別変更済み、取消済み、長文、大量、未送信あり、競合あり |
| 日時 | 日跨ぎ、週・月・年の境界、月末、閏年、過去・未来、異なるタイムゾーン、DSTの欠落・重複時刻 |
| 端末 | 前景、背景、画面ロック、強制終了、再起動、承認済み別端末、未承認端末、旧版混在 |
| 通知・表示 | OS許可あり／なし、家事のみ／予定のみ／両方OFF、ライト／ダーク、通常文字／拡大文字 |

アカウント切替中の遅れた受信、除名中の送信待ち、期限切れ復旧中のローカル編集、繰り返し分割中の他端末編集、通知予約中のログアウトは必須の複合条件とする。
