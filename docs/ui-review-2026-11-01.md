# 2026-11-01 ホーム・カレンダー・グループ設定の修正

## 表示と操作

- ホームの日付・ヘルプ・グループ・設定をスクロール領域の外へ固定した。期限を過ぎた家事は「今週／来週」の手前に常時表示し、強い囲みと説明の繰り返しを除いた。期限切れの回に「期限間近」とは表示しない。未完了の期限切れを先にする従来の並び順は保持した。
- 「担う」は行の中に収め、押せる範囲を細い枠で明示した。ホーム末尾の「実施履歴」「ゴミ収集日」を共通部品にし、個人・共有とiOS・Androidで揃えた。予定がない週の文章は「今週の予定はありません。」「来週の予定はありません。」に短縮した。
- カレンダーの家事件数は数値で表示する。利用者の最新指定により、点・横棒とその表示設定を廃止した。ゴミ・一般予定・日付の枠線は維持する。旧表示設定の保存値は読み込めるままにしている。
- 分割された月の最初の実日付にも左線を付け、月の最初の週にも横線を通した。年月を押すと年・月を選んで移動できる。日・2日・リスト等の表示形式を維持し、選択日の数字は移動先の月末までに収める。

## タブへ戻ったときの表示

続く利用者の指定により、アプリ起動後や別タブから開くカレンダーは月表示に揃える。最後に選んだ「1日／2日／リスト」は端末に保持し、月の日付を選ぶとその形式で開く。年月の明示移動は、その場で使っている表示形式を保つ。設定などを上に開いて戻る操作と、ホーム・カレンダー・家事・家電のタブ移動を区別する。

家事の説明を開いたまま別タブへ移動した場合、次は家事一覧から表示する。操作は個人・共有とも同じタブ部品で扱い、家事の保存先や完了履歴は変更しない。

年表示では今月を枠と淡い背景で、今日の日付を塗りつぶした丸で区別する。予定追加は高さ44ptを保って横幅を広げる。設定の共有グループ・端末間同期・端末管理の矢印は、文字の直後ではなく行の右端へ揃える。

## スケジュールだけを初期値に戻す

個別設定のスケジュール項目の末尾と、家事一覧設定の末尾に控えめな復元操作を置いた。全件の復元には確認を表示する。周期・負荷・実施期間・移動幅・休日優先・日次固定・洗濯条件が対象で、有効／無効、名前・手順、完了履歴、担当方式や担当者は保持する。

組み込み家事は編集可能な名前で照合せず、安定したカタログIDで初期値を引く。メーカーが周期を指定していない家電家事では、利用者が選んだ周期を勝手に30日へ置き換えたり無効化したりしない。個人の既存データに初期値が記録されていない独自家事は復元対象にしない。共有の独自家事は最初の認証済み設定を使う。

個人の全件復元は同一SQLiteトランザクションで行う。共有は既存の管理者権限・表示時の設定版を検証し、1回の署名付き保存でまとめる。担当の再対応が曖昧な場合や他端末の設定が変わった場合は、途中だけを保存せずに止める。

共有コマンドの依存ソースが変わるため、ソース契約を`liflow-shared-2-draft-41`へ更新した。既存のdraft-40／39／38とその署名済み履歴は対応を維持する。設定の復元のために既存グループへ互換更新を強制しない。

## グループ設定の項目

通常の入口は日常の操作を上、初回設定後の変更が少ない項目を下にまとめた。

| 項目 | 内容 |
| --- | --- |
| 家事ごとの設定 | グループ用の家事設定、個人家事からの追加、ゴミ収集日 |
| 申請・承認 | 日時変更、担当変更 |
| メンバー・招待 | メンバー一覧、所有者端末での招待・参加承認・除名・引継ぎ |
| グループ名・ルール | 名前、グループの種類、共通ルール。地域は必要なときに展開する |
| 同期 | 未送信件数、最終同期、手動同期。通常は閉じる |
| 更新・復旧 | 互換更新と署名付き復旧の確認。通常は閉じる |

個人のGoogle連携は通常設定の「Google連携」、この端末の共有通知は「通知・ウィジェット」へ移した。ホームの実施履歴を設定一覧へ重ねて並べない。画面の移動だけで同期と状態の再読み込みを走らせない。同期の失敗と復旧待ちの注意は、項目を閉じていても確認できる。

所有者は「メンバー・招待」を開くと参加申請も自動で取得する。「参加申請を確認」をもう一度押す手間を除き、失敗した場合は空の申請一覧と区別して再試行を出す。閉じたメンバー欄のために手動同期のたび招待一覧を取得する処理も除いた。承認は確認番号を照合して明示的に実行する。

設定の初回読み込みが失敗した場合、待機表示のままにせず再試行できるようにした。招待・除名・退出の権限、暗号鍵、確認操作、未送信変更の保存は変更していない。

操作回数の確認では、個人の家事詳細はホームから「設定→分類→家事」の3操作、グループの家事詳細も「グループ→家事ごとの設定→分類→家事」の4操作である。一般設定からグループ側を選び直す経路では4操作になる。これをアプリ全体で最小の手数にできたとは評価しない。個人・共有の保存先と分類を判別するための操作と、単に同じ内容をもう一度開く操作を区別して検査する。参加申請の確認は、後者の1操作を除いた。一般設定の「共有グループ」も、参加中なら中間ページを挟まずグループ設定へ直接進める。

## 個人設定の全体（利用頻度に合わせて再整理）

一度は全項目を直接操作できる形へ変更したが、利用者から、変更の少ない通知・地域・誕生日まで常時展開すると、普段使う家事設定や連携を見つけにくいと指摘された。タップ数だけを減らす方針を改め、利用頻度と設定後の変更頻度で並び順・初期の開閉を選び直した。

| 順番 | 項目 | 初期表示 |
| --- | --- | --- |
| 1 | 家事ごとの設定 | 分類を直接表示。長い家事一覧は分類から展開 |
| 2 | 生活リズム | 閉じる。頻度と休日を見出しの横に表示 |
| 3 | 共有グループ | 参加中ならグループ設定への直接リンク |
| 4 | Google連携 | 閉じる。接続・取得中・失敗・再接続必要を見出しに表示 |
| 5 | ゴミ収集日 | 管理画面への直接リンク |
| 6 | 通知・ウィジェット | 閉じる。通知のオン／オフを表示 |
| 7 | 天気予報・洗濯 | 閉じる。保存済みの市区町村を表示 |
| 8 | 誕生日 | 閉じる。登録件数を表示 |
| 9 | アカウントと端末 | ログイン中だけ表示し、閉じる |
| 10 | 実行記録・クレジット | 閉じる |

家事の個別設定は引き続き「設定→分類→家事」の3操作。低頻度の項目は見出しから1回で操作を表示する。現在値を見るだけなら開く必要はない。通知・天気の保存失敗、Googleの再認証・同期失敗・再試行待ちも閉じた見出しで区別する。読み込み中を未設定・未接続とは表示しない。見出しの現在値は画面読み上げにも渡す。折りたたみで自動保存や再試行を止めず、入力を閉じても未保存の内容を消さない。

天気の見出しを閉じた際は地域候補の検索を停止する。入力途中の文字は残し、再び開いただけでは検索を再送しない。誕生日の件数は起動時から共有する個人カレンダーの状態を参照し、そのためだけのネットワーク取得や家事の再計算は追加しない。

利用者が要求した表示方針の変更に合わせ、必須回帰の `personal-settings-direct-controls` を `personal-settings-selective-disclosure` へ変更した。分類への直接アクセス、保存済みの概要、低頻度の項目の初期折りたたみ、共有・Google連携が誕生日より前にあること、展開後の操作・自動保存を保護する。通知の許可、Googleの直列実行、保存失敗時の再試行、アカウント照合など既存の動作検査は削除していない。

実画面の冷起動検査で、本人用設定をFirebaseのアカウント復元より先に読み、エラーのまま残る経路を発見した。本人確認を待ち、アカウント一致を再確認してから保護された設定を読むよう修正した。同じアカウントを復元する途中に保存済み共有表示を一度消す経路も除き、タブと移動先の構成が一瞬切り替わるのを防いだ。異なるアカウントなら以前の表示は破棄し、保存権限も引き継がない。

前回のシミュレーターReleaseのXCTestで、起動直後のグループ設定、個人設定の上位項目と、保存先選択のない家電追加ダイアログを確認した。年表示の今月枠と今日の丸、横長の追加ボタン、別タブから月表示に戻ること、日付から最後の2日形式へ進むこと、家事タブが一覧に戻ることも確認済み。今回の折りたたみ方針への変更は下記の追検査で区別する。家電・PDFの保持については[家電APIの検査記録](appliance-public-api-2026-10-31.md)に分けて記録する。

Androidのダークモードでは、共通スイッチのつまみに背景色を使っていたため、つまみが背景に溶け込んでいた。Androidだけ明るいつまみに変え、iOSの標準描画は維持した。旧家事一覧に残っていた色の個別指定も除き、共通部品に揃えた。暗色でのつまみのコントラストと操作コールバック・値の保持を必須回帰へ追加した。Android 10実機で通知のオン／オフを目視し、元の値へ戻してからアプリを再起動し、設定の保持も確認した。

## 起動とアイコン

ネイティブの起動画面は最初の利用可能な画面まで保持し、枠付きの読み込みカードを挟まない。保存済み共有表示の認証と、実操作前の権限復元は維持する。これは1秒以内の起動を保証する変更ではない。直前のAndroid実機5回測定では、コールド起動から家事操作可能まで平均3.113秒であり、1秒の目標は未達である。

iOSのダークアイコンと暗い起動画面用に`assets/images/liflow-icon-dark.png`を追加した。既存の白い家事の図形と余白を保ち、背景をアプリの暗色へ寄せる指示で、組み込みimagegenの画像編集を使用した。元の青い画像は保持する。Androidのadaptive iconは白い図形の重心を基準に余白を調整し、丸いマスクの安全範囲も検査した。

Androidのヘッダー欠けは、Expo SymbolsのMaterial文字が固定サイズの枠内でシステム文字拡大とフォントの上下余白を受けるために発生していた。同SDK版のAndroid描画に限って文字拡大を無効にし、フォント余白を除いて中央へ揃えるpostinstall補正を加えた。通常の本文の文字拡大、操作領域、iOSのSymbol描画は変えていない。SDKの描画コードが変わった場合は補正を黙って適用せず検査で止める。

## Expo SDK 58の互換更新

最初の公開コミットのNative設定CIは、オンラインで確認されるSDK推奨パッチ版との差分で失敗した。同じSDK 58内で`expo install --fix`を適用し、Expo Doctorの20項目成功を確認した。SDKのメジャー更新や非互換更新による検査回避は行っていない。

新しいCLIは内部ファイルの配置とプラグイン検証を変更している。依存セキュリティ回帰は新しい実際のCLI validatorを呼ぶように更新し、不正なプラグイン・URL・MCP引数の拒否、Zodの要素検査前の上限拒否、node-forgeの偽造署名拒否と正常な署名の互換性を保持した。
