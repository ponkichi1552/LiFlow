# PDFだけで始める家電登録

2026年11月13日の指示により、個人・共有とも製品情報を手入力せず、添付したPDFから製品情報とお手入れ項目を同じ1回のAI呼び出しで取得する。

画面・解析API・暗号化されたworker入力・再解析の照合を変更する。既存の利用枠、再送の同一性、入力PDFの検査、保存・共有の権限は維持する。

## 実装

- 家電一覧から直接PDF登録へ進む。メーカー・製品名・型番はPDFと手順を同じ解析で読み取る。別の製品名ダイアログや追加の製品入力は置かない。
- 新しいリクエスト形式をHTTP受付、暗号化されたworker入力、クライアントのポーリングまで通す。旧形式は既存アプリ・受付済み処理の互換性のために維持する。
- PDFに製品情報がなければ推測で補わない。複数の型番が書かれた資料では型番と条件を保ち、再解析は登録済み製品と一致した場合だけ保存できる。
- PDFを選び直すと古い解析結果と共有前の確認を無効にする。最新の選択ファイルを解析・保存に使い、連打・画面を離れた後の遅い応答・古い保存ハンドラーによる二重処理を防ぐ。
- PDFの利用確認は送信先の説明と解析操作にまとめる。PDFの検査、利用枠、端末確認、共有権限、既存家事との競合検査は残す。

## 一覧・詳細の見直し

2026年11月13日5:48の画面指摘も反映した。

- 家電一覧を家事一覧と同じ連続した行にし、重複する「登録した家電」の見出しとメーカー・型番の再表示を削減。独自の名前には不足する製品情報を補う。
- 家事と家電の追加ボタンを下部タブのすぐ上・同じ主要ボタンに統一。本文を覆う絶対配置を家電一覧から外した。
- 個人・共有の詳細を中央の共通ヘッダー「お手入れ方法」に統一。製品名と件数をコンパクトにし、項目番号と大きな周期なしの注意枠を外した。
- 手順の後にメーカーの実施条件・道具・安全上の注意を表示する。条件や禁止事項自体は保持し、空の道具見出しは表示しない。解析結果の確認画面にも同じ手順部品を使う。

## 保留事項

公開されているメーカー公式PDFで実OpenAIを1回呼び出したが、`AI_SERVICE_NO_RESULT`となった。後続の読み取り専用の確認では`401 expired_secret_key`だった。利用者が実API検証の保留を選択したため、それ以後のOpenAI呼び出しは行っていない。

今回のシミュレーターには解析APIの公開URLも設定されていないため、登録画面は「解析に接続できませんでした」と表示し解析を無効にする。端末確認を回避して成功扱いにはしていない。新コードのAPI公開・実解析・実機確認・GitHub反映はこの記録の完了範囲に含まれない。
