# LiFlow UI/UX共通ルール

2026年11月9日、利用者との画面調整で決めた判断基準。新しい画面と既存画面の改修では、このルールと共通部品を使う。利用者の新しい指示で変更した場合は、ここも更新する。

## 優先順位

1. 初見で、何を押すと何が起きるか分かる。
2. 目的までの操作と視点移動を少なくする。
3. 同じ役割の操作を同じ場所・形・色にする。
4. 文字量と余白を抑え、必要な内容を読み取りやすくする。
5. 表示を先に返し、保存・同期のために利用者を待たせない。

見た目をそろえるために、権限判定、保存済みデータ、編集中の再試行を削らない。

## 入口と画面移動

- 設定の入口は`SettingsList`と`SettingsRow`。項目名を左、必要な件数・状態と青い右向き矢印を右へ配置する。別ページが必要な項目に同じ形を使う。
- 長い家事一覧、メンバー管理など、独立して操作する内容は詳細画面へ進む。短い関連項目は同じ詳細画面に並べ、開く操作を挟まない。
- 共有設定では、長くなる家事一覧・メンバー管理・ルールの編集だけ詳細画面へ進む。短い申請状況と同期・復旧は、その場に常時表示する。空の申請のために画面を移動させない。
- 日時・担当の申請は同じ欄へまとめる。同期・更新・復旧も一つの欄にまとめる。メンバーを招待するボタンは参加申請の下に置き、単独の見出しや背景を足さない。
- グループの家事選択は同じ一覧で完結させる。個人にしかない追加家事も未選択の候補に並べ、チェックした時だけグループへ追加する。個人の履歴は共有せず、既存の共通家事は重ねて追加しない。
- 同じ設定を複数箇所で見せる場合は、編集部品・保存先・競合処理を共有する。グループの家事設定に置くゴミ収集日と、設定トップから開くゴミ収集日は同じ共有データを編集する。
- 折りたたみは、長い任意の証拠、競合候補の詳しい内容、地域の検索などに限る。少量の設定を隠すための開閉や、二重の折りたたみを作らない。
- `SettingsHeader`で戻るを左上、画面名を中央に置く。本文で同じ画面名を繰り返さない。下部タブの表示を画面ごとに勝手に変更しない。

- 設定を離れる操作を未保存入力で止めない。無効な入力・保存に失敗した下書きは移動時に自動で破棄する。正常な入力の自動保存は画面移動と独立して進め、保存待ちや再試行で移動を遅らせない。長い文書をスクロールしただけでは下書きを破棄しない。既に保存済みの変更・共有の承認・復旧記録は保持する。

## 見出し・背景・区切り

- 関連する入力と操作は`SettingsGroup`または`SettingsPanel`の淡い背景でまとめる。`SettingsGroup`の見出しは背景の外へ置く。
- 背景だけで区別できる場所に、囲いと細線を重ねない。ページの入口は一覧の区切り線でそろえる。
- 少量の表示選択や、ページ末尾のアカウント変更・ログアウトに、分類のためだけの背景や見出しを追加しない。
- 未接続などの接続状態は`SettingsStatus`の控えめな補足文字にそろえる。読み込み中・失敗・未接続・停止・接続済みは区別する。通知の個人／共有ラベルは同じ`SettingsLabel`を使う。
- 件数は対象から離さず、見出しのすぐ隣か一覧の同じ行へ置く。未読込を0件にしない。未登録なら「未登録」だけを表示し、「登録済み 0件」を重ねない。
- 空欄の手順・道具・注意事項や、行動につながらない内部状態は通常画面に出さない。エラー・保留と必要な操作は残す。

## ボタンの意味と色

設定の操作は`SettingsAction`を使い、画面側で独自の色を指定しない。

| 役割 | 指定・表示 |
| --- | --- |
| 通常の操作 | `intent="normal"`。淡い背景内では`placement="panel"`で白系の面・枠線なし。ページ背景上では`placement="page"`で白系の面・控えめな枠線。 |
| ページの主要な確定操作 | `intent="primary"`。青い面を使う。同時に目立つ主要操作を増やさない。単なる再読込・設定移動は主要操作にしない。 |
| 削除・除名・解除・退出 | `intent="destructive"`。赤文字で示す。ログアウトなどの末尾操作は背景や見出しで強調しない。 |
| 移動・選択中 | 青い矢印、チェックボックス、連結した選択欄を使う。通常の補助操作まで青くしない。 |

- 欄全体の主操作は欄の幅を使う。編集・再読込・その日だけの非表示など、その対象だけに働く操作は短くする。短いボタンでも押せる範囲を確保する。
- ON/OFFは`SettingsCheckbox`、排他的な選択は`SettingsSegments`。スイッチとチェックを同じ意味で混在させない。
- ライトの白系背景をダークへ固定値で持ち込まない。`plannerColorsForScheme`の`surface`・`elevated`・`border`・`ink`・`muted`・`accent`・`warning`を使う。
- ライトの青文字とチェック・主要ボタンは、指定画像の元の明るい青にそろえる。チェックと主要ボタンの文字は白。ダークの配色は別に保つ。
- 通常の保存は自動保存。新しい確認操作を独断で増やさない。既存の除名・権限変更・復旧の確認は、その機能の保護条件に従う。

## 文言と状態

- ラベルは「誕生日を登録」「カレンダーで休日を登録」のように、対象と操作結果が分かる短い日本語にする。
- グループの全権限を持つ役割の画面上の呼び名は「管理者」に統一する。表示名の変更に合わせて権限や保存形式を変えない。
- 分類名やRGB値も共通の入力欄と同様、淡い背景内に通常の面色の入力欄を置く。入力欄の形を項目ごとに変えない。
- 入力の説明とプレースホルダーを重複させない。長い仕組みの説明はヘルプへまとめ、操作に必要な制約だけを近くに残す。
- 設定の誕生日は本人の日付だけを登録する。名前・メモ・地域・分類を入力させず、日付選択の完了で保存する。他の人の誕生日はカレンダーで登録・編集する。
- 処理中もボタンや本文の場所を保つ。成功を装わず、未確定・保存失敗には再試行を用意する。古いアカウントの結果を新しい画面へ反映しない。
- 以前の表示と入力を保持して更新する。別ページから戻っただけで全内容を消して読み直さない。不要な通信や全体計算を画面表示の前提にしない。
- 完了した家事はチェックと名前の取り消し線で示す。ホームでは完了だけを理由に背景や区切りの色を変えない。
- 実施履歴は個人・共有とも共通ヘッダーと月・日ごとの連続した一覧を使う。個人の通常記録は家事名と完了日時だけを見せ、展開を追加しない。共有は家事名と完了日時を先に見せ、展開すると当時の担当者と実施者だけを表示する。完了を取り消した記録は履歴一覧から外し、内部の取消記録は保持する。展開できる通常行も、展開しない行と同じ高さにそろえる。承認待ち・条件未達成など、誤認につながる状態は残す。履歴には完了の取り消しボタンを置かず、完了・未完了は家事のチェックで変更する。承認待ちの回答と既存の権限判定は維持する。統合ホームの履歴には本人の個人記録も含め、現在のグループ記録の学習用コピーを重ねて表示しない。

## 改修時の確認

- 新しい見た目を作る前に既存部品を確認する。共通部品で表せない場合は、同じ意味の役割として部品を拡張し、この文書へ判断基準を残す。
- 見た目の寸法や色そのものを固定するテストは作らない。ナビゲーション、入力・保存・下書き、権限、同期、エラー、アクセシビリティは維持する。
- 変更した範囲の操作テストとlint・型検査を行い、シミュレーターのライト／ダークで文字切れ・階層・タップ・戻る・スクロールを確認する。全体確認は`docs/testing-strategy.md`の最終検証で行う。

- ホームでは同じ予定回を今日と今後のおすすめへ重ねて出さない。同じ家事・同じおすすめ日に完了済みと次回分が重なる場合も一行にそろえ、内部の予定回と履歴は保持する。別の日・別の作業意味の回を名前だけで統合しない。
