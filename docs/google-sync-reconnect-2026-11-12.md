# Google再接続・アカウント操作の修正と検査

検査日：2026年11月12日（日本時間）。同じ作業コピーの `main`、基点 `e5652ce` に対する未コミットの変更。iPhone 12 / iOS 27.2 のRelease版と、Housework QA / iOS 27.0 のシミュレーターへ、保存データを保持して導入した。

## 原因と変更

- CalendarのON設定が残っていても、端末のGoogle認証と保存済みのアカウントが一致していない状態があった。通常の同期再試行は認証画面を開かないため、同じエラーを繰り返していた。
- iOSの保存資格情報の復元に失敗すると、明示的な再ログインまで進めない経路があった。前景で利用者が接続を選んだ場合だけ、アカウント選択から再認証できるようにした。
- アカウント変更・ログアウトの表示がFirebase共有ログインの有無に依存していた。個人のGoogle連携だけでも設定末尾の同じ操作を使えるようにした。個人利用の変更でFirebaseへ新しくログインしない。
- Calendarの操作を、未接続・要再認証・接続済みに応じて「Googleと接続」「Googleに再接続」「今すぐ同期」へ切り替える。端末のアカウントと権限を確認し、確認中も区別する。ネットワーク障害だけで既知の認証エラーを解除しない。
- アカウント別の対応表・取得位置・未送信変更を保管し、元のアカウントへ戻したときに復元する。Tasksの再認証後も対象の接続を有効にしてから同期する。
- ログアウト時はTasksとCalendarの自動同期を停止し、Googleの端末内認証を終了する。Firebaseへログイン済みなら同じ利用者も終了する。進行中の資格情報復元によるログインの復活と、別の利用者に対する遅れたログアウトを拒否する。
- 実機の追加検査で、ログアウト後にCalendar欄だけ古い接続表示が残る問題を発見した。アカウント変更の通知を購読し、画面を開き直さず再確認するよう修正した。古い非同期応答が表示を戻さない回帰テストも追加した。

ローカルの家事・完了履歴、Google上の予定・タスクをログアウトやアカウント変更のために削除しない。Googleの許可そのものを取り消す操作は行わない。

## 実機で確認した操作

利用者所有の元アカウントをA、別アカウントをBとして記録する。メールアドレスや認証情報はこの文書へ転記しない。

| 操作 | 観測結果 |
| --- | --- |
| 既存エラーからの再接続 | アカウント選択へ進み、最終同期時刻が更新された。従来のアカウント不一致エラーが解消した。 |
| A → B | 別アカウントを選択できた。未設定のBではCalendarの同期はOFFで、「Googleと接続」を表示した。BでのCalendar同期は有効にしていない。 |
| B → A | 元の保存先と同期ON設定が戻った。手動差分同期が完了し、最終同期は01:16:57へ更新された。 |
| ログアウト | Native認証が終了し、同期がOFFになった。保存DBの `enabled=false` と `quick_check=ok` も確認した。 |
| 表示修正後のログアウト | 同じ画面でチェックがOFF、「Googleと接続」へ切り替わり、ログアウト項目も消えた。再表示操作は行っていない。 |
| ログアウトから再接続 | 元のアカウントを選択してCalendar同期を再開でき、01:24:09の完了を確認した。 |
| 最後の再接続とアプリ再起動 | 01:25:38の同期完了後にLiFlowを終了して再起動した。追加の認証画面なしで接続が復元され、最終同期は01:27:36へ進んだ。「今すぐ同期」・アカウント変更・ログアウトの表示を確認した。 |

Tasksと空き時間取得は、検査前と同様にOFFのままとした。この検査では新たなタスクや予定を投入していないため、変更・完了・取消しの実サービス往復検査の代わりにはならない。OSによる自然な背景実行の成功も、この前景検査からは主張しない。
