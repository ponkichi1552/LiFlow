# 署名付き受領と切替手順

共有の家事・予定と本人端末の設定・空き時間は、端末の保護された保存領域に書き込んだ後に受領を署名する。共有は保存済みの位置と適用したスナップショット、本人同期は設定と空き時間それぞれのダイジェストを使う。署名はプロジェクト、対象グループまたは本人アカウント、参加登録、承認された鍵の世代に結び付ける。

ワーカーは変更できない承認履歴を検証し、各承認端末の公開鍵で署名を確認する。最初の有効化には、全端末がその時点の最新データを保存した証明が必要になる。有効化後は全端末が対象データを受領したら暗号本文を消す。24時間を過ぎても、現行の承認端末に復旧可能なコピーを確認できるまで原本を保持する。共有の変更履歴では、グループ管理者による復旧に備えて、管理者端末の保存位置までは削除でき、その位置より新しい原本は保持する。別端末に復旧用として再配送した本文は、受信端末の署名を確認した時点か24時間後に消す。受領済みまたは期限切れの要求は新しい書き込みを締め切り、分割データの削除ごとに元の要求と復旧ロックを確認する。

署名は、承認鍵を持つアプリが保存を完了した時点の証明になる。対応アプリと端末の鍵が信頼できることが前提で、端末の初期化、故障、鍵の侵害後にコピーが残ることは保証できない。保存した端末がすべて失われると、サーバーから消去した本文は復元できない。閉鎖が承認済みのグループは、受信先が残っていなくても期限後に消去する。

## 段階的な切替

1. 従来の削除ワーカーが稼働していた環境では、先にそのインスタンスを停止する。新しいFirestore Rulesとインデックスを配備し、端末向けビルドで `EXPO_PUBLIC_SHARING_EPHEMERAL_DELIVERY=1` を設定する。新ワーカーには、リポジトリルートから `server/account-device-api/Dockerfile` で作ったイメージを使う。旧方針がある対象では `--pause` が1回のトランザクションで新方式の停止状態へ切り替え、旧端末の自動削除もRulesで止める。
2. `LIFLOW_FIREBASE_PROJECT_ID` を接続先に設定する。管理用認証で `npm --prefix server/account-device-api run delivery:work -- --enroll shared GROUP_ID` または `--enroll private USER_ID` を実行すると、削除を停止した状態で署名付きの対応状況を集め始める。
3. 各承認端末で同期し、`npm --prefix server/account-device-api run delivery:status` で件数を確認する。`approved` は承認登録、`ready` は現行承認の署名を確認できた登録、`caughtUp` は最新データの署名が一致した登録を表す。旧版の受領記録だけの登録は含めない。`invalidAuthorityScopes` と `recoveryLockedScopes` を確認する。
4. 共有・本人同期それぞれで端末再起動後もデータが残ることと、期限後に別端末から復旧できることを検証用データで確認する。確認した対象範囲に `--enable shared GROUP_ID` または `--enable private USER_ID` を実行する。有効化トランザクションでも最新データに対する全端末の署名を照合する。削除プロセスの起動には `LIFLOW_ENABLE_DELIVERY_ERASURE=1` も設定する。
5. `--pause` で対象範囲の自動消去を停止する。既に消去した本文は、対応版の承認端末同士で復旧する。復旧処理中のグループは、現在の承認世代の復旧ロックが解消するまで消去を保留する。署名済みの履歴整理を明示的に実施した場合は、その手続きで確定した範囲を整理できる。

コンテナにはアカウントAPIのHTTP起動が既定で設定されている。削除には常駐ワーカープールを使用し、起動コマンドを `node --experimental-strip-types /app/server/account-device-api/src/sharing-delivery-main.mjs` に指定する。ワーカー用の認証には対象プロジェクトのFirestore権限を設定する。コンテナからの状態確認や切替にも同じ実行ファイルを使い、続けて `--status` などの引数を渡す。

## 独立レビュー

6.2-astraが保存の証明、承認履歴、停止からの切替、期限消去、再配送を確認した。次の指摘を実装と検証に反映した。

- 共有履歴は別端末や旧版の保存領域から復旧するときも元の署名とサーバーの受付記録を照合する。通常受信と既存データの移行のどちらからも、欠落範囲だけを復旧できる。
- 管理者端末の保存位置を超える共有履歴は保持する。隔離中の原本や次の鍵世代に備えた一時ファイルが先頭にあっても、後ろにある条件を満たした項目を処理する。分割削除中に復旧ロックが取得されたら残りを保留する。
- 本番SDKで使用できる監視に変更した。本人同期では、古い承認世代のCalendarを保持していても、現行世代の本人設定を受領確認できる。
