本人の保護ストレージに保存された地域・休日・実施可能時間帯・負荷上限を、実際の個人配置計算へ接続した。ログインのない利用は既存の端末内設定を使う。別のアカウントの設定を共通のhousehold_settingsへコピーする処理は追加していない。

共有の正式な定義・担当・完了履歴から、本人担当と未担当の負荷を参照する。他人担当、完了規則で解放された回、消化済みとして抑制された回を予約へ重ねない。並行完了を家事回ごとに正規化し、当日に本人が実施した有効な完了だけを消化済み負荷へ加える。他人の実施は本人の消化量にしない。実時刻のある予約は本人の地域へ換算し、時刻のない予定は合意した元の民事日付を保つ。

共有の本人向け推奨を先に計算し、その負荷の周囲へ個人家事を配置する。個人の結果を再び同じ共有推奨へ入力する循環は作らない。共通の正式な周期・期間・担当・planHashは変更しない。共有推奨は表示中の月とは独立した一定範囲で作り、同じ検証済みの共有sourceHashであることを確認して各画面・通知・Tasks計算へ再利用する。範囲外や異なる共有版を、同じ結果として扱わない。

同名の個人・共有家事は既存の一対一の名前照合を使い、個人側の未完了負荷を二重に予約しない。個人の定義・有効状態・履歴は保存したまま、共有中の個人用周期編集もその時点の順序付き履歴へ記録する。退出後は保存した個人設定が使える。季節家事と曖昧な複数候補は名前だけで統合しない。

一つのrepository操作は本人入力を一度だけ取り込み、分離したSQLiteトランザクション用接続にも同じ入力を引き継ぐ。表示キャッシュは入力元・アカウント・設定世代を検査する。保存直前にも保護された設定の版、共有の参加状態・ローカル世代と別接続のSQLite更新を検査する。最後の書き込み後に変化が分かっても、COMMIT前なら完了・取り消し・次回予定を同じトランザクションで取り消す。

共有負荷の増減は該当する日を再配置の入力に含め、候補日がつながる未来の個人回だけを再計算する。今日・明日・過去・毎日固定の保護は維持する。同じ入力の再読込はモデル・履歴を学び直さず、同じ予定を書き直さない。共有の一般予定も個人配置の時間控除へ使い、競合して読めない共有予定を空き時間と判定しない。

説明書が周期を指定しない個人用家電家事では、スケジュール初期化／固定周期解除を「必要なとき」へ戻す。仮の30日周期を表示・生成せず、有効状態・説明・原本の完了履歴は保持する。固定周期を再設定した場合は新しい学習区間で再開する。旧「周期を保持する」検査は共有側の互換性検査として残し、個人側の受入条件は採用済み11月4日仕様に更新した。
