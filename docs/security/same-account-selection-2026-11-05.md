# 同一アカウントの2台検査：アカウント選択の準備

## 対象と現在地

利用者の指定に従い、Androidで使用中のGoogleアカウントにiPhoneを合わせる。既存の別アカウントでの検査結果とは分けて記録する。現在はアカウント選択の修正と関連自動検査を完了し、通常Releaseへの導入・実アカウントでの確認を進めている。2台のGoogle Tasks作成競合の実機PASSはまだ確定していない。

## v16の実機で見つかった不足とv18の修正

v16は基本認証の選び直しを追加した段階だった。利用者から「以前連携したGoogleアカウントを選択してください」が残ると報告され、旧個人Google Tasksの連携先・予定IDが同じSQLiteの有効な接続情報として残っていたことを確認した。アカウント不一致の防止自体は維持されており、以前のGoogleの予定IDを新しいGoogleアカウントへ送ることは拒否されていたが、切り替えの操作として不完全だった。

v18では明示的なアカウント切り替え・接続・再認証の操作に限り、以前のTasks接続情報と紐付けを端末内へ保管してから、選択したアカウントの接続情報へ移る。新規アカウントには以前の予定ID・リストIDを引き継がず、未接続から開始する。戻ってきたアカウントには保存済みの接続情報を復元する。通常の同期処理からの無断の紐付け変更は、引き続き拒否する。

Tasksの状態・紐付け・未反映の完了状態と、従来のFreeBusy設定・日別取得キャッシュは、Googleの利用者IDごとに保存する。Tasksの未確定作成記録と差分取得キャッシュは既存のアカウント別の保存を維持する。退避は100行ずつ読み書きし、大きな全件JSONにはまとめない。家事・設定・履歴は変更しない。Google側のデータは削除せず、切り替えだけで新しいTasks権限を要求しない。

双方向Calendarの接続情報もGoogleの利用者IDごとに保持し、復元時には接続世代を進めて古い通信の結果を拒否する。取得位置、送信途中の変更、Google由来の予定は元のアカウントに残す。従来のTasks情報の切り替えとCalendar接続情報の切り替えは同じSQLiteトランザクションに含め、途中の失敗時は両方とも戻す。

既に動いているGoogle処理が終わってから接続情報を切り替える。ネイティブのGoogle利用者とFirebase利用者を確認し、確定直前にも照合する。15秒の期限は読み取り専用の本人確認待ちに適用し、SQLiteの確定・取り消し完了は必ず待つ。端末の本人確認が遅延した場合、保存済みデータを残して取り消し、後から届く結果で確定しない。

同じアカウントを選び直したときは共有作業領域の選択を保持する。設定画面では他のGoogle操作と同じロックを使い、成功後に表示を更新して古い不一致エラーが残らないようにする。接続済み表示にもアカウントの一致確認を加えた。新しい処理は接続操作時に読み込み、設定を開いただけでアカウント情報を退避しない。

v18の関連201件、lint・型検査・機能契約・共有Scheduler契約はPASS。`account-switch-v18-batched-final-area.log` ほかに記録した。実機へのv18導入とアカウント切り替えの最終確認は進行中であり、この自動検査を実機PASSとは扱わない。

## 修正

従来の共有ログインは保存済みのGoogleセッションを復元するため、別のアカウントを選び直す入口がなかった。個人設定の「アカウントと端末」に「Googleアカウントを変更」を設け、既存Nitro Google Sign-In 2.3.0の明示的なアカウント選択を使う。設定を開いただけでは認証モジュールを読み込まない。

切り替え前に設定の自動保存を完了させ、入力途中の不正・未確定値があれば切り替えずに該当設定を表示する。旧作業領域の書き込み完了も待つ。連打・操作中の利用者変更・画面離脱後の遅延処理から別の認証を開始しない。

選択のキャンセルやFirebase認証の失敗では保存済みの作業領域選択を消さない。成功時は、返されたFirebase UIDの端末鍵を使用し、利用者が変わった場合のみ選択ポインタを解除する。以前のSQLite、家事・履歴・端末鍵・グループ所属情報は削除しない。アカウントの統合・プロバイダーの紐付け・Googleトークンの失効は行わない。新しいアカウントで旧アカウントのTasksやCalendarへ送ることは、既存のアカウント一致検査が拒否する。

ネイティブ選択結果と現在のGoogleユーザーが一致しなければ認証を中止する。前景での利用者操作に限定し、バックグラウンド処理から選択画面を開かない。Tasks／Calendarの追加権限はこの操作に含めない。

関連132件PASS、lint・型検査PASS。iOS／Androidの選択・キャンセル・アカウント差し替え拒否・前景制限、認証の並行実行、旧作業領域保持、実際の設定画面からの呼び出し、未保存入力保護を検査した。必須機能契約にも登録した。証拠：`/tmp/liflow-resume-20261104/account-selection-final-area.log`、`account-selection-final-lint.log`、`account-selection-final-typecheck.log`。全体3307件PASSはこの修正前の結果であり、現在の最終全体検査とは扱わない。

## 実機の残り

通常Releaseの更新後、iPhoneで明示的な選択画面を開き、指定アカウントを選ぶ。パスワードや追加確認が必要な場合は本人の端末入力を待つ。既存共有グループへの新しい端末鍵の承認と、同一Google／Firebase利用者・同一Taskリストを確認してから、作成・再試行・完了・取消し・再起動の2台検査を行う。ここまでの自動検査や既存の別アカウントでの同期を、その実機検査へ読み替えない。
