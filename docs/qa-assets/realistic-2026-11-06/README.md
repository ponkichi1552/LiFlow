# LiFlow 調査に基づく生活様式テスト入力集

## 結論と位置づけ

28の生活プロフィール × 10の行動変種 × 90/365/730日 × 2乱数系列 = **1,680ケース**。
調査で確認できる生活の多様性を軸にした合成データです。実在する1,680人の履歴でも、人口を代表する分布でもありません。時間・日付・変化率など、調査にない値は明示的なテスト仮定です。

**検証済みは生成データの整合性だけです。LiFlow本体を実行していません。** `expected_invariants`はアプリに接続した際に守るべき期待で、満たされたという結果ではありません。ここで本体の予測精度や性能を証明するものではありません。

## 根拠

- JILPTのシフト制非正規労働者調査：固定・交代・不定シフト・呼出し。
- MyVoiceの洗濯機利用調査：家族と本人の実施の違い、早朝・昼・夜。
- プラネットの洗濯調査：毎日・週数回・週1回、世帯頻度と本人担当頻度の違い。
- 国土交通省のテレワーク調査：在宅と出社の混在。
- 大学生協の学生生活実態調査：曜日ごとに変わる授業や生活。
- 就業構造基本調査・社会生活基本調査：介護と仕事の併存、世帯構成と分担の多様性。
- ダスキン大掃除調査：年末集中、普段分散、外注。

詳細は `sources.json` と `evidence/`。調査の対象集団・集計単位が異なるため、それらの割合を掛け合わせて仮想人口を作っていません。性別、年齢、職業から本人の行動をアプリが推定する仕様を追加するものでもありません。根拠記事や図表を転載せず、出典を記録しています。

## 構成

- `generate.py`：固定シードの生成と整合性検査。Python標準ライブラリのみ。
- `cases.jsonl.gz`：機械可読の全ケース。gzipを解凍すると1行1ケース。
- `case_index.csv`：一覧。プロフィール、行動変種、日数、観測件数。
- `examples.json`：少量の展開済み例。
- `invariants.json`：20の要求事項。
- `directed_cases.json`：重要な境界を明示した少数の受入ケース。
- `validation.json`：生成件数と整合性検査結果。
- `SHA256SUMS`：生成物のハッシュ。

## ケース内容

`clock`は開始日・タイムゾーン・観測期限。すべてAsia/Tokyo。タイムゾーン移動・夏時間は未収録です。

`calendar`は曜日の繰返し・週番号による早番遅番・日跨ぎ予定・明示的な例外。週番号は開始日を含むISO週を0とします。`end_day_offset=1`は翌日終わり。休日の曜日は月曜0〜日曜6。**予定のタイトルから睡眠や忙しさを推測しません。**

`chores`は日数型・個別固定・共有・季節固定を区別します。ゴミ収集は周期学習する家事を作らない契約です。期間と所要時間は人工例です。季節の5月15日・10月15日・12月20日も機械試験値で、地域別最適日の提案ではありません。

`observed_history`は本人が記録した完了日（開始日からの経過日）と時刻。日0の最初の完了を含むため、**学習可能な間隔数は完了数−1**です。初回のアプリ起動前の履歴は与えていません。未記録を未実施と扱いません。

`evaluation_only_hidden_events`は合成上の未記録実施で、**アプリには渡してはいけません**。人間の本来の希望を知ったことにもしません。家庭の実際の状態を評価する目的にも使いません。

`lifecycle_events`は初期化、当日翌日の急用、天気取得失敗、同期の重複配送、同一回の別ID完了、後続設定変更、完了取消などのオーバーレイ試験です。基本の完了列に対して単に重ねるだけでなく、テストアダプターでイベントを時系列に適用してください。特別な完了イベントの回IDは通常列と独立です。取消後も無関係な設定を残します。

各ケースの未来の完了列は評価側だけが保持します。**時刻を進めながら、その時点までの情報だけをアプリへ渡してください。** 全期間の情報を最初から読ませると将来情報漏洩です。

## 28プロフィール

固定早朝、固定夜間、長時間通勤、土日勤務、交代シフト、夜勤、日跨ぎ家事、呼出し、分割勤務、不定休、会議中心の在宅、学生、担当あり二人暮らし、担当未定二人暮らし、異なる勤務の同居、通院送迎等、昼間の余裕、断片化した空き、短期不在、長期不在、同居人の普段担当、記録漏れ、季節家事あり、季節家事なし、年末集中、日常分散、外注、在宅出社混在。

これらは互いに排他的な人口分類ではありません。一人に複数の特徴があり得ます。ケース数はカバレッジのため均等で、発生確率ではありません。

## 10行動変種

安定、揺れ、継続的長周期化、一時的長周期化、交互、漸増、記録漏れ、提案追従の評価対象、月末型、設定変更。

同一の行動変種を複数生活へ組み合わせていますが、この組合せの確率は調査から推定していません。すべての家事へ一律に同じ変種を適用せず、毎日・共有・個別固定には固定の規則を保っています。

「提案追従」は静的列だけでは再現できません。該当ケースには別途0/50/100%の感度分析を指定し、アダプターが予測を受けて生成する必要があります。割合は実測でなく仮定。**この入力集だけで閉ループ試験済みとは呼びません。**

## 開発と評価の分離

同じプロフィール・変種・観測期間に、別シードのdevelopment/holdoutを用意。これは分布外評価の証明ではありません。調整はdevelopmentのみで行い、holdoutで再評価してください。将来は生活変種そのものを留保する評価も追加します。同じ入力の複製で件数を増やすことを避けるため、種ごとの独立性ではなく具体値の重複も確認します。安定パターンで同一結果になる場合は別の実証とは数えません。

## 必ず出す評価値

1. 観測日数と有効間隔数。
2. 3間隔に達した割合。
3. 採点できた事前予測数と、期限内に次の完了がなく未採点の数。
4. 変化前後・生活群別の誤差。全体平均だけで結論を出さない。
5. 追加操作要求、今日明日の自動移動、固定値変更、二重負荷、季節移動の件数。契約違反はゼロが必要。
6. 再配置件数、候補なし、同期・取消時の一貫性、実コードの処理時間。

180日周期は最初の完了から3間隔まで540日、365日周期は1095日必要です。730日以内では学習できない例もそのまま残します。未採点を0誤差と置かないでください。

## 未実装・未確認

この資材はアプリのスキーマに接続するアダプター、4方式の実装、複数家事最適配置、同期通信、端末間競合を提供していません。期待規則とデータを将来のCodex実装テストへ移すためのものです。独立した以前の周期模型は `/liflow_benchmark` の別資材で、この資材に適用済みではありません。

## 再実行

`python generate.py`

生成後に `validation.json` を確認。過去のテスト結果をアプリ本体のPASSへ読み替えないでください。
