# UI変更中のテスト方針

2026年10月31日、利用者からテストの取捨選択を任されたため、見た目を固定する検査を整理した。画面や操作経路を変更するときは、新しい利用方法に沿って操作テストを更新する。

## 自動検査に残すもの

- 入力値の保存・復元、初期設定、家事の有効化、周期、ゴミ収集日の繰り返し。
- 完了・取り消し、優先順位、二重タップ、保存失敗、読み込み失敗、下書き、再試行。
- 個人とグループの分離、アカウント変更、権限、暗号、同期、競合、再送、課金を伴うAIの利用制限。
- 戻る・開く・切り替える操作が正しい対象へ届くこと。閉じる操作で未保存の入力を失わないこと。
- OS別のPicker・Widget・色リソース・モジュール解決、古いAndroidでの互換性。
- ダーク／ライト切り替えで文字の色が失われないこと、パレットの最低限のコントラスト、操作のアクセシビリティ情報。
- 大量の家事を一度に全部描画しないこと、古い画面からの非同期結果が現在の表示や保存を壊さないこと。

`ui`、`screen`、`layout`というファイル名だけでは削除しない。SQLiteや同期・保存の結果を確認しているテストは、画面を通した重要な機能検査である。

## 自動検査から外すもの

- フォントを28／22／19／17／14などの固定値に縛る検査。
- 戻るボタンやタブの文字サイズ、太さ、余白、高さ、数字の単位欄の幅、内部Viewの個数・位置。
- 特定の背景色をRGB値で固定する検査。分類の同一性や利用者が選んだRGB値の保存は引き続き検査する。
- 入力欄を並べる順番、枠線・padding、装飾記号、説明文やフッターの位置。
- アコーディオンが特定のabsolute配置・測定高さで実装されていること。開閉操作と展開状態のアクセシビリティ情報は残す。
- `FlatList`の描画設定を2・2・5などに固定する検査。文書全件を一括描画する退行は引き続き検査する。
- カレンダー入力をcontrolled／uncontrolledのどちらかに固定する検査。最新の入力が一度だけ正しく保存されることを確認する。
- アイコンをSVGで描くことや、Pathの配列が異なることだけを確認する検査。ゴミの種類・別名とアイコン識別子の対応は残す。

表示専用の7ケースを削除し、混在したテストから表示の固定値だけを除去した。数値設定・ゴミ収集日・家電の周期の保存、戻る操作、ゴミ出しの非表示と復元、カレンダー保存は維持する。アプリ本体のUIはこの整理では変更していない。

## 最後に実画面で確認するもの

UI変更がまとまった後、iOS／Android、明暗両モード、小さな画面と拡大文字で確認する。

1. 見出し・本文・補足の優先順位、文字の読みやすさ、色に頼りすぎない状態表示。
2. 数字と単位・手順番号・チェック・矢印の位置、文字切れ、過剰な余白、びん・PET・缶などのマークの見分けやすさ。
3. 押せる箇所の分かりやすさ、押せる範囲、キーボードやホームインジケーターとの重なり。
4. タップ直後の反応、完了と取り消し、並び替え、連打時の挙動。
5. 画面移動や復帰時の不要なスクロール、選択した日付の維持、縦横スワイプの競合。
6. 展開・折りたたみ・モーダル終了・戻るアニメーションの方向、ちらつき、引っ掛かり、本文のはみ出し。
7. 同名の個人／共有家事、未完了／完了、推奨日前／期限間近の見分けやすさ。
8. 通信断・保存失敗・権限不足・空の一覧でも、状態と次にできる操作が理解できること。

Nodeの画面ハーネスが成功しても、実際の描画位置やアニメーションが滑らかだとは証明できない。最終確認では、対象のOS・ビルド・画面・操作と観測結果を記録する。

`docs/feature-contracts.json`の`manualReview`はこの確認先を示す。自動検査を通ったことだけで、その視覚要件まで合格したとは扱わない。

## 実行範囲

テスト整理では、編集した操作テスト、契約登録の検査、lint、型検査を実行する。UI変更が一段落したら`npm run check`、隔離Auth／Firestoreの結合検査、両OSの実画面検査を通す。`npm test`やCIから機能・セキュリティ検査をまとめて外すスキップ設定は設けない。

## 作業中と最終確認の分担（2026年11月5日）

作業中は変更の影響範囲に対応するテストを実行し、通過したら次の作業へ進む。未変更の機能を毎回全件実行しない。契約変更・型変更・保存形式変更のように複数機能へ影響する場合は、実際に影響する境界のテストを選ぶ。失敗時は原因に対応する検査を追加する。

依頼された変更がそろった最後に、既存の全件テスト、Cloud検査、lint、型検査と必要な実画面確認を実施する。途中の限定テストの成功を全体完了として扱わない。
