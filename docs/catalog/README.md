# カタログの参照元と更新方針

2026年11月1日、利用者が指定したGoogle Docsの36項目を取り込んだ。説明・道具・手順・注意・豆知識・実施条件・周期の原文は `household-care-source-2026-11-01.txt` に保存し、内容のSHA-256、取得日、更新日時、見出しURLを `household-care-2026-11-01.json` に記録する。Google Docs自体は編集していない。

目安時間はドキュメントよりも、同じ依頼に添えられた36項目の固定時間表を優先する。例えばレンジフード35分、浴室25分、洗濯30分、洗濯槽洗浄10分。ドキュメントの90・360・675分などをアプリの目安時間へ取り込まない。

```sh
node scripts/generate-household-care-guide.mjs
node --experimental-strip-types scripts/generate-housework-guide.mjs
```

`--check`で、原文・時間表と配布する内容が一致するか確認できる。回帰検査は36項目の全フィールドと固定時間表を照合する。

## 周期の扱い

文書の周期と、Schedulerに必要な日数の初期値を区別する。週1回は7日、月1回は30日、年2回は180日として数値化し、幅があるものはその範囲内で頻度モードの初期値を設定する。これはアプリ向けの近似であり、暦の毎月・毎年の特定日を厳密に再現する設定ではない。

複数工程に周期がある項目では、冷蔵庫は週1回の食品確認、エアコンは14日ごとのフィルター確認、ペット設備は毎日の衛生確認を定期予定の中心にする。庫内全体の清掃、季節前の試運転、週1回の寝床清掃などの違いは、実施条件・手順の原文を残す。

炊飯後の使用ごと、加湿器・除湿機、浄水器、水槽、自治体のごみ収集、暖房シーズン前は一律の固定周期を設定しない。`requiresCycleSelection`を使い、周期が決まるまでは無効にする。内部形式が要求する正の数値は、実際の周期として表示・実行しない。周期の入力と解除、初期値への復元、初期設定からの誤有効化も検査する。ゴミ収集日の曜日・隔週・毎月の既存機能は変更していない。

## 既存データ

既存項目の削除については確認を出しており、現時点では既存項目を残す安全な方針を採用する。旧20件のうち同じ仕事に対応する10件はIDを維持し、残り10件も保持するため、組み込みカタログは合計46件。今回指定された36件に含まれる値と、従来から保持する10件の値を混同しない。新たに増える26件は勝手に有効にしない。

個人DBのカタログ版を4へ上げ、旧標準値と一致するフィールドだけ更新する。ユーザーが変えた名前・手順・周期・有効状態・負荷などは保持する。完了履歴、担当、開始状態を別の家事へ移さない。失敗時はカタログ版を含めてロールバックする。変更なしの再初期化で定義を書き直さない。

共有グループも管理者の端末から署名付き変更とOutboxへ保存する。一般メンバーからは更新を発行しない。明示削除、同時編集の競合、個別の共有設定・完了・担当は保持する。検証済み移行がない旧グループへ、推測で書き込まない。個人側の変更を共有側へ無条件にコピーしない。旧名と新名の正確な対応を使い、移行中に個人と共有の同じ仕事が二重にならないようにする。

共有の計算契約はdraft45へ更新し、draft44以前の対応版も保持する。所有者による通常の版更新と復旧経路を維持する。

## 検査中に見つけた既存処理

短い周期で過去の実施機会を繰り越した場合、同じ予定の未実施周期数が次の読み込みで減少し、不要なSQLite更新が発生していた。推定で進めた基準日と同じ未完了予定の照合を保ち、同じ読み込みで値が揺れないよう修正した。実際の完了や周期・期間の変更は従来の失効判定に従う。

大きくなった共有カタログでは、設定の検査データが100件のOutboxページを超えた。100件の上限を緩めず、検査ではページ長と全待機件数を区別する。画面テストも全行が同時に描画される前提を外し、スクロールして全項目へ到達できることを確認する。

起動時に保存済み画面へ描画機会を渡す待機が、必ずNativeのアニメーションフレームを受け取れる前提になっていた。直接リンク先に保存済み画面がない場合にも復元を継続できるよう、描画待ちには50msの上限を設ける。通常の描画機会と、フレームが一度も届かない経路を別々に回帰検査する。この上限は起動完了時間の保証ではない。

さらに、起動画面を閉じる処理自体もアニメーションフレームを待っていた。Androidの起動画面は描画を止めるため、「画面が描画されるまで起動画面を閉じない」という循環になり得る。表示可能な面のレイアウト完了時に、追加フレームを待たず閉じる形へ修正する。Nativeの表示を残したまま要素情報だけ更新される失敗を成功へ数えず、実際の取得画像も照合する。

説明の連結ページと説明一覧には、共通ページと異なり起動画面を閉じる呼び出し自体がなかった。各表示面のレイアウト完了を同じ終了処理へ接続し、ホームを先に開かなくても起動できることを検査する。

また説明の閲覧まで管理画面として扱い、保存済みホームと同じ家事説明を含んでいても初期表示から除外していた。説明と一覧は認証された保存済み表示を利用し、管理・編集は従来どおり現在の権限確認を待たせる。検査では復元前に説明が見えること、未検証のコントローラーを作らないこと、Outboxを書き換えないことを照合する。

## 画面とデータの確認

iOS 27シミュレーターのRelease版で、浴室25分・レンジフード35分・洗濯槽洗浄10分・暖房器具15分と周期未設定、戻る操作の入口、タブの維持をXCTestと取得画像で確認した。Android 10のSony実機でも同じ項目を照合し、最終版はアプリを終了した状態から洗濯槽洗浄のリンクを開き、ホームを先に表示せず本文と10分の目安が見える実画像を確認した。開発サーバーは使用していない。これは全機種での1秒以内の起動を保証する計測ではない。

更新時にシミュレーターの既存DBファイル15件が保持されたことを確認し、更新前に存在した完了記録23件・14件、共有の署名済み記録28件・89件が変わっていないことも別途照合した。AndroidはアプリのUIDと初回インストール日時を維持した上書き更新であり、初期化・削除は行っていない。検査ログ・失敗した試行・個人データを含む退避物は非公開のローカル保管先へ残し、このリポジトリへ追加していない。
