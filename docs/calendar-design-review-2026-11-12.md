# カレンダーの表示別UI見直し（2026-11-12）

## 共通化する範囲

設定画面の一覧・淡いカードを、カレンダー全体へ移植しない。色の意味、操作可能・無効の区別、押せる範囲、戻る・追加・確定の役割は共通にする。日付の位置と時間軸はカレンダーの目的に合わせる。判断基準は `ui-design-rules.md` の「カレンダーへの適用範囲」に追記した。

| 対象 | 判断・変更 |
| --- | --- |
| 上部・下部の操作 | 追加は右上。戻る・年月・表示切替と並べる。検索だけ「今日」の隣へ置く。検索・下書きの表示はカレンダー領域内に収め、下部タブへ重ねない。 |
| 月 | 週の高さをそろえ、予定到着や家事件数で伸縮させない。最大4件の予定枠を確保し、分類は文字・背景で表す。分類の縦線を置かない。 |
| 年 | 今月・今日の目印を保つ。祝日の日付を着色する。 |
| 1日・2日 | 選択した日を同じ帯で示し、今日の表示とは分ける。土日をまたぐ2日も同時に表示。左右で補助情報の行数が違っても家事件数を下端でそろえる。家事なしは開く操作を置かず、未取得と区別する。 |
| 家事と収集日 | 家事は簡潔な行にする。展開した家事欄は時間軸のスクロールでも残す。収集日は日付のそばへ1回だけ表示し、日別の非表示・未取得・競合状態を保持する。 |
| リスト | 日付を左へそろえて縦に追える形にする。空の日に「家事なし」と「予定なし」を二重に並べない。家事がある日は空予定の文を重ねない。 |
| 予定入力 | 日付・時刻を開始／終了の行でまとめ、終日とチェックを近づける。メモは1行から内容に応じて伸ばし、長い場合だけ欄内をスクロールする。 |
| 日付・時刻・繰り返し | ピッカーの見出し・確定位置をそろえる。繰り返しの単位を連結選択にし、重複する見出しを削る。毎月の曜日指定を直接選べる形にする。 |
| 分類 | 既存色・カスタムRGBの入力、分類保存・閉じるの意味を保ち、入力部品と操作の見た目をそろえる。 |
| 家事追加 | 既存候補と新規作成を保つ。選択した家事名の二重表示をやめ、必須欄の名前から候補を選び直せるようにする。 |

白・黒の分類色は表示時だけ補正する。保存済み分類色やGoogle側の色は書き換えない。検索は保存済みの予定名・場所・メモを対象とし、検索入力のたびに通信や全繰り返し展開を行わない。下書きの明示的な保存・破棄、更新競合と共有権限の判定は維持する。

## 日本の祝日

[内閣府の公表データ](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html)のCSVを同梱した。取得元・取得日・原本のSHA-256は `src/features/calendar/japanese-holidays-data.json` に記録している。対応は公表済みの1955〜2027年。将来の未公表日を推測しない。

月・年は日付の色だけ、1日・2日・リストは日本語の祝日名を表示する。読み上げには名称を含める。Google由来の祝日カレンダーの行を重ねず、通常の予定を祝日名だけで削除しない。

祝日は予定レコードとして保存せず、時間の予約・家事不可の判定・Googleへの送信に含めない。SQLiteとGoogle同期の実コードを使う検査で、祝日の表示だけでは送信が発生せず、同日に登録した通常予定は送信対象になることを確認した。実Googleサービスへの送信検査とは区別する。
