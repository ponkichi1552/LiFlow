# カレンダーの日常操作の見直し

- 起動中の表示状態を維持。カレンダーから離れて60秒以内は表示方式と日付を維持し、60秒以降は月表示へ戻す。プロセスを終了した後は月表示から開始する。
- 家事検索は表示元と同じ取得済みデータを対象とし、結果からその日付と家事欄へ移動する。
- 個人家事の行本体から今回の実施日を変更する。完了チェックは独立。対象回・計画版・定義を保存時に再確認し、周期と履歴を変更しない。
- カレンダー通知は家事通知と独立した全体スイッチと予定ごとの通知時刻を持つ。通知なしを初期値とし、選択肢は開始時・10分前・1時間前・前日。通知設定は端末側に保存し、共有イベントやGoogleへ送信しない。
- 既存の即時カレンダー初期化・再起動後の詳細表示記憶という検査契約は、今回の利用者指定に合わせて置き換えた。

## 検証

- 関連する24ファイルの286検査が成功。通知の許可拒否、家事通知との独立性、保存失敗のロールバック、共有コミット後の通知保存失敗・再試行、アカウント境界、季節家事の今回の日付変更を含む。lint・型検査も成功。
- 初回の全件実行は4093件中86件失敗。変更した契約・スキーマ番号・新しい起動ブリッジの検査を合わせた再実行は4097件中4016件成功・81件失敗。夜間に実行すると予定が翌日へ配置される既存の行同一性検査は、朝の時計を固定して意図する条件を安定させ、関連286検査では成功している。全件成功とは扱わない。
- npm testの前段は共有v2のソース互換性チェックで停止。今回の変更前と変更後の正式スケジューラーの実ソースダイジェストは同じ `2f62930d95b410aa78edfb3128f535d1812d955d2fde63673b0e845344bcda91` であり、登録値 `8dc6858d4f44961374fb4f7e0bfeb7eb6eaf34d5a68b9254a24f71235f13f888` との不一致が作業前から存在する。互換性番号・ハッシュを今回のために書き換えていない。
- Cloud検査の再実行は環境条件を満たさず未実施。手元のFirestore Emulator 1.22.0はJava 21を要求し、利用可能なJava 17で起動するとUnsupportedClassVersionErrorになる。プロダクションへ接続して代替していない。
