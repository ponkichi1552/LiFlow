# 予定名から週・月の繰り返しを設定する

## 指示と実装前の検討

2026-11-16 04:28 JSTから検討を開始した。利用者は「毎週火曜日」「毎月21日」も文章から設定したいと依頼した。現在は繰り返しを含む文章を解析対象から外している。既存の単発予定の解析を維持し、明確な週の曜日・月の日付指定を繰り返しと初回日へ変換する。

入力からの仮動作は次のとおり。予定名は原文をそのまま表示し、既存の日時欄と繰り返し欄の値を更新する。説明用の行・確認操作・サーバー通信は増やさない。

- 「毎週火曜日18時から食事」→ 予定の地域の今日以降で最初の火曜日、18時開始、毎週。
- 「毎月21日に支払い」→ 今日以降で最初の21日、毎月。日付のみの指定では時刻や終日を勝手に補わない。
- 同じ曜日・日付が今日なら今日を初回にする。31日などが存在しない月は、その日が存在する次の月を使う。登録後も既存の「その日がない月はスキップ」の周期規則を使う。

## 自己評価と確認する境界

初見の利用者は入力した文章と、直下に見える日時・繰り返しで結果を確認できる。同じフォームと保存操作を使うため、操作や配置を増やさない。端末内の短い規則で処理し、AIやネットワークを使わない。

手で変更した日付・時刻・終日と繰り返しを優先する。手動の繰り返し設定をタイトルの再入力で解除しない。自動設定された表現を文章から取り除いた場合は、自動設定した項目だけ元の値へ戻す。既存予定・複製・家事・誕生日への自動適用制限は保持する。

複数の周期、異なる曜日や日付との競合、無効な日付、不明確な周期は推測して単発予定へ変換しない。入力途中で「毎週」までしかない場合も、誤って火曜日や時刻だけを採用しない。24時による翌日への移動と、週・月の基準日が食い違わないことを確認する。

実装前に、既存のフォームへの接続・保存値・月末と年跨ぎ・手動編集の保持・表現を消した時の復元を整理する。2分以上の検討と自己評価を終えてからコードを変更し、純粋な解析・入力状態・画面からの保存の回帰で確認する。

手動で繰り返しの種類・終了日を選んだ場合は、その繰り返し設定をタイトル解析から保護する。カスタム設定から戻った空の新規フォームでも、すでに選んだ周期を保護する。既存の選択コールバックだけへ接続し、部品・配置・ナビゲーション・保存先・共有権限を変えない。SDK 58の参照資料と既存の入力接続を確認した。既存テストの「毎週火曜18時は拒否」という1入力は、今回の依頼で有効になるため受理側へ移し、その他の拒否条件は維持する。
