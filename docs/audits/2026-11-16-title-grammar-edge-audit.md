# 予定名の自然文日時・周期・期間の独立監査

対象は `tests/calendar-title-grammar-edge-cases.test.mjs`。製品コード・既存テスト・契約登録はこの監査担当から変更していない。

## 検証の根拠

利用者の7入力と明示された意味に従う。年なし月日は次に来る実在日、明記された過去年はそのまま、2月29日は次の閏年とする。終日の1週間は開始日を含む7日、時刻付きの期間は指定された暦日数後の同時刻とする。ランチから時刻を補わず、誕生日という本文から予定種別・分類を変えない。省略は原文の日時・周期・期間部分だけに作用し、自動入力が成立しない入力と省略後が空になる入力では原文を保つ。

暦の期待値には製品の日時・周期ヘルパーを使用せず、整数によるGregorian暦、世紀の閏年規則、曜日計算、翌日の列挙を使う。

| 検査の範囲 | 確認条件 |
| --- | --- |
| 年なし月日・毎年月日 | それぞれ366の実在月日。次に来る2月29日も含む |
| 週周期 | 可能な127曜日集合を月曜・日曜・年末の3基準日で確認 |
| 月周期 | 1/11/12/21/28/29/30/31日の全2要素組を4つの短月・閏月・年末条件で確認 |
| 期間 | 6開始日×10日数×終日/18時開始。別途1/2週間・相対日の区別 |
| 大まかな日時の候補 | 利用者の追加指示に従い、11時頃・約11時・4/11頃・約4/11・約1週間・1週間程度/ほどを明示数値の下書き候補として採用。省略表示では修飾語も取り除く |
| 文法の拒否 | 複数候補・除外・連結・不正日付・未対応の年/日付範囲・不正漢数字・過大/符号付き期間・以内/以上/以下の意味違い |
| 原文・手動入力 | Unicodeの原位置、全角・漢数字の本文、OFF、手動ロック、削除による復元、配列の非共有 |
| 画面の対象制限 | iOS/Androidハーネスで既存・複製・誕生日・家事・読み取り専用の入力を保護 |

これらは有限状態・暦境界の検査条件であり、条件数を独立した不具合件数に置き換えない。発見は以下の5原因群にまとめる。利用者から「11時頃を11:00として扱ってよい。詳細はユーザーが決めればいい」、さらに「大まかで少し直すだけなら全入力より楽。明らかに誤りでなければ大まかでよい」と追加指示があった。明示数値のある概数は拒否する検査から下書き候補として受理する検査へ変更し、不具合件数から外した。

## 再現した問題

| 原因群 | 修正前の入力と実際 | 期待 |
| --- | --- | --- |
| 一部の日付だけを受理 | `4月11日か12日旅行`、`4月11日、12日旅行`、`4月11日〜17日旅行`は4/11だけ。`明日以外に旅行`は明日。`26年4月11日旅行`は26年を無視、`二万二千二十四年5月22日旅行`は2024年 | 全体を未確定として自動入力を行わず、表示も原文 |
| 不正な期間を確定 | `明日から-6日間旅行`は負号を無視して6日になる | 符号・小数・過大・以内など意味が変わる期間は拒否 |
| 助詞除去で本文を欠落 | `毎月21日 はじめての学校`は「じめての学校」、`毎月21日 からあげを食べる`は「あげを食べる」 | 本文の語頭をそのまま残す |
| 年周期の24時で閏年の意味を変更 | `毎年2月29日24時集合`は毎年3/1の予定になる | 表現できない年周期は推測せず拒否 |
| 不正漢数字の桁を欠落 | `毎月二十一一日旅行`は21日、`毎月十十日旅行`は20日 | 不正数は拒否。有効な二十一・二一・二〇二四・二千二十四を維持 |

再現例は実装担当へ共有し、製品コード側で修正済み。各原因群を新規テストへ残した。
