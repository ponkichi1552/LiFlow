# 稼働サーバーの照合と更新

## 配備前の変更案と自己評価

2026-11-16、利用者のサーバー更新の依頼に基づく。東京リージョンの既存3サービス（本人端末の復元API、天気API、天気取得worker）、既存Scheduler、FirestoreのRules・indexを照合する。家電解析の公開API・解析worker・配送workerは、このリージョンのCloud Runサービス・Job・worker pool一覧には存在しなかった。存在しない配備を更新済みと記録しない。

更新対象は、検査を通過した正本ソースから作ったイメージとRules・indexとする。ビルド入力は明示したソースとlockfileだけを梱包し、環境ファイル、端末データ、資格情報、ローカルの成果物を含めない。既存のCloud Build用サービスIDと非公開Artifact Registryを使い、新しい権限や秘密鍵を作らない。

既存のimage digest、revision、traffic、設定の指紋を記録する。APIの認証、実行ID、環境変数、ingress、IAM、同時処理数、最大インスタンス数を保ち、新revisionを既存revisionへ影響しない状態で確認してから切り替える。切替後もHTTPSの応答とIAMの拒否条件を照合し、異常なら記録したrevisionへ戻す。配備前後の端末受信は、配備成功とは別の結果として記録する。

サーバー保存を減らす目的から、配送本文やAI処理入力を新たなログ・バックアップへ複製しない。アプリ3台は一時配送フラグ0のため、今回の更新だけで共有本文の削除を始めない。旧端末を含む全承認端末の復旧準備・永続保存・受領・期限切れ復帰の条件が揃うまで、削除の有効化を分離する。

自己評価：既存の権限と費用に関わる上限を維持して段階的に切り替えることで、利用者のログインし直しやデータの再入力を避ける。常時workerの新設は、実行環境・権限・費用・停止手順・受領条件を確認するまで行わない。OpenAIの有料実API検査の保留は維持する。

## 実施結果

稼働構成の読み取りを完了した。イメージの更新・Rulesの更新・削除の有効化は、まだ実施していない。結果は実施後に追記する。
