# 稼働サーバーの照合と更新

## 配備前の変更案と自己評価

2026-11-16、利用者のサーバー更新の依頼に基づく。東京リージョンの既存3サービス（本人端末の復元API、天気API、天気取得worker）、既存Scheduler、FirestoreのRules・indexを照合する。家電解析の公開API・解析worker・配送workerは、このリージョンのCloud Runサービス・Job・worker pool一覧には存在しなかった。存在しない配備を更新済みと記録しない。

更新対象は、検査を通過した正本ソースから作ったイメージとRules・indexとする。ビルド入力は明示したソースとlockfileだけを梱包し、環境ファイル、端末データ、資格情報、ローカルの成果物を含めない。既存のCloud Build用サービスIDと非公開Artifact Registryを使い、新しい権限や秘密鍵を作らない。

既存のimage digest、revision、traffic、設定の指紋を記録する。APIの認証、実行ID、環境変数、ingress、IAM、同時処理数、最大インスタンス数を保ち、新revisionを既存revisionへ影響しない状態で確認してから切り替える。切替後もHTTPSの応答とIAMの拒否条件を照合し、異常なら記録したrevisionへ戻す。配備前後の端末受信は、配備成功とは別の結果として記録する。

サーバー保存を減らす目的から、配送本文やAI処理入力を新たなログ・バックアップへ複製しない。アプリ3台は一時配送フラグ0のため、今回の更新だけで共有本文の削除を始めない。旧端末を含む全承認端末の復旧準備・永続保存・受領・期限切れ復帰の条件が揃うまで、削除の有効化を分離する。

自己評価：既存の権限と費用に関わる上限を維持して段階的に切り替えることで、利用者のログインし直しやデータの再入力を避ける。常時workerの新設は、実行環境・権限・費用・停止手順・受領条件を確認するまで行わない。OpenAIの有料実API検査の保留は維持する。

## 実施結果

正本 `e0ec346916076486f59e71016ea2bdc94741e53a` の明示したソースから、本人端末APIと天気runtimeの2イメージをCloud Buildで生成した。両ビルドが成功し、digestを固定して配備した。ソース梱包は個別ファイルのSHA-256と再読込を照合した。ビルドが受領した後、Cloud Storageへ一時アップロードした2つのソース梱包はgenerationを指定して削除し、404を確認した。正本ソース、ローカルの梱包とマニフェスト、復旧に必要な旧revision・imageは保持する。

| サービス | 配備したrevision | 通信の配分 |

| 本人端末の復元API | `liflow-account-device-audit-e0ec346` | 100% |
| 天気API | `liflow-weather-audit-e0ec346` | 100% |

最初に旧revisionへ100%を維持して新版を起動し、設定の指紋とdigest、準備完了、検査用URLの応答を確認してから切り替えた。全3サービスのIAMポリシーは配備前後で一致した。実行ID・環境変数・リソース上限など、imageとrevision以外の設定も維持した。新しいサービスや権限を追加していない。

新版の検査用URLは9条件、切替後の通常URLは6条件を確認した。APIのhealth 200、本人確認のない復元要求401、天気の既存地域200・同じETagで304かつ本文0 bytes、未知地域404、書込405、AI経路404、未認証worker403を含む。切替後は自然なSchedulerの実行が新版workerへ届き、HTTP 200と`weather_worker_batch`、`attempted: 0`を確認した。上流METへ新しい検査用地域の取得を強制していない。

FirestoreのRulesをコンパイル・配備し、配備原文のSHA-256が正本の`b38cf178c351d3ce8a07c4254515c12899b7288b04b11c9a1c090c19978cd7f2`と一致した。indexも配備した。天気専用DBのRulesは元から正本と一致しており変更していない。既存の期限付き端末申請・利用制御のTTLは引き続き有効で、共有本文の新たな削除を有効化していない。両DBのPITRは読み取り時点で無効だった。これは全バックアップ・全ログ保存先の調査完了を意味しない。

Cloud Buildに記録された旧ソースの一時オブジェクト2件は既に404だった。旧image digestとrevision、Rules原文、traffic、IAMのチェックポイントを別に確保しており、旧ソースオブジェクトが取得できたとは記録しない。

公開家電解析API・解析worker・配送削除workerの新設は行っていない。全端末の一時配送・復旧準備が未完了のため、共有本文削除の切替は未実施。OpenAI実APIの保留も維持する。配備結果の機械可読記録は[受領記録](../qa-assets/physical-2026-11-15/server-update-2026-11-16.json)を参照。
