# カレンダーの直接操作と月表示の時刻

追記: この記録は最初の直接操作実装時点の証拠。後続の利用者指示で、繰り返しの移動範囲選択・個別変更を保持する全体編集・端の自動スクロール・元に戻すを追加した。最新の仕様と検証範囲は [月表示の自動スクロール・移動範囲・元に戻す](2026-11-14-calendar-autoscroll-and-undo.md) を参照。

既存の main 上で作業し、今回以外の未コミット変更を保持。GitHub公開と物理端末の操作は行っていない。

## 変更

- 月表示に開始時刻を添える場合、1行の名前には直下の2行目、2行の名前には3行目へ表示し、空行を作らない。予定・家事件数・収集日を先に確保し、週の高さは維持する。
- 編集シートの「予定を複製」で、選択した回を独立した未保存の新規予定へコピーする。元のID・同期リンク・共有の操作証明は引き継がない。
- 1日・2日の空き時間の長押しで、日付と5分単位の開始時刻が入った新規予定シートを開く。保存するまでは予定を作らない。
- 1日・2日の通常予定は長押しドラッグで日時を変更できる。離したときに1回だけ保存し、実時間の長さを保つ。繰り返しは選択した回だけを変更する。
- 月表示にも長押しドラッグを追加。時刻を保って日付だけを移す。終日予定は日数を維持し、複数日にまたがる予定の途中を持った場合も全体を同じ日数だけ動かす。短いタップは従来どおりその日の詳細を開く。
- 移動の長押しを250ミリ秒に短縮。月の見出し・空白セル・画面外は移動先にしない。スクロール量と実際の画面位置から移動先を解決し、ドラッグ中だけ月のスクロールを止める。
- 移動中の枠は文字幅を狭めない別レイヤーにし、日付のラベル・他の週に入った予定も切らない。月の移動を実画面で検査した際に2行の名前の枠が1行になる問題も見つけ、月用の子要素から時間軸用flexを外して修正した。
- 移動の権限・保存先・版を再確認する。読み取り専用予定・家事回・祝日・誕生日を通常予定の移動処理では変更しない。中断では保存せず、失敗時は元の位置へ戻す。保存中は仮の移動位置を表示し、スクロールを止めない。
- `tools/computer-gesture/` に汎用のMac画面操作CLIを追加。任意のアプリ・ブラウザー・シミュレーターの座標で長押し・連続移動・解除を行う。アプリ固有のラベル・端末ID・データ作成は持たず、移動途中で止めて実画面を撮影できる。現在のmacOS入力許可を確認し、新しい許可は自動で要求しない。

## 自動検査

- 最終bundleのソースに対し、変更に対応する89件が通過。iOS・Androidの画面ハーネスで入力・複製・権限変化・保存先切替・競合・中断・保存待ち表示・スクロール復帰・月表示の日付のみの移動・終日・繰り返しの範囲を確認。関連するSQLite保存・版競合・繰り返し例外・月境界も検査した。
- 既に個別変更した繰り返し回の本文は `recurrence: none` のため、本文から変更範囲を判定すると全体変更になる不具合を再現。親の繰り返し設定から範囲を決めるよう修正し、元の起点・例外の版・その回だけの変更が保たれる検査が通過した。
- lint・型検査・iOS Release用bundle出力・署名検証が成功。694件の機能契約と118件のCloud検査の登録も検証した。全件テストやCloud実サービス検査を実行したという意味ではない。

## 実画面と保存結果

- iOS 27.0「LiFlow 誕生日確認」の月表示で、短い名前の直下へ時刻が表示され、2行の名前の直下には3行目の時刻が表示されることを確認。
- 「旅行の打合せ」から新しい入力シートへ複製し、名前を変更して保存。元の予定と独立した2件が表示された。
- 2日表示の空き時間を長押しすると、11/16 12:45〜13:45の未保存フォームが開いた。入力せず閉じた。
- アクセシビリティ操作で確認用予定を14:00〜14:30から14:05〜14:35へ変更し、編集画面と読取専用SQLiteで確認。その後、利用者から自然なドラッグで翌日へ移動できたとの回答を得た。利用者が後から動かした位置を、先の手動回答の保存証明として読み替えていない。
- 汎用CLIで2日表示の確認用予定を押したまま移動し、保持中・移動中・解除後を撮影した。左上の枠と日時表示が切れないことを実画面で確認。
- 月表示は350ミリ秒の実マウス長押しで起動。11/15 → 11/17 → 11/24 → 12/1と移動し、週境界・月境界・スクロール後の座標を確認した。12/1への保存後も14:40〜15:10のまま、revisionは4から3回の移動で7になった。移動ごとに新しい予定を作っていない。
- 月表示を短くタップすると、予定編集シートを開かず選んだ日の2日表示へ進んだ。
- 月の移動中の実画面では、2行の予定名と時刻を囲む枠が収まり、別の週に移っても欠けないことを確認。共有用シミュレーターのダーク表示でも保持中の枠と日付を確認し、元の位置で解除すると編集シートを開かず枠が消えた。
- 移動確認用の予定だけを通常のドラッグで11/15へ戻し、読取専用SQLiteで14:40〜15:10・revision 9を確認した。
- 確認用・個人用・共有用シミュレーターへデータを保持して更新。それぞれ9・14・19ファイルのSHA-256一致をインストール直後に確認した。
