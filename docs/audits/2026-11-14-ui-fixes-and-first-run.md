# 全画面UIレビューの修正と初回設定

対象は `2026-11-14-full-ui-review.md` の F01〜F28 と、利用者が追加指定した初回設定。今回の実装・確認を記録する。元のレビュー、既存の未コミット変更は保持した。公開・実機更新は行っていない。

## 初回設定の変更

必ず通る画面は「家事を選ぶ」「生活リズム」の2つ。普段の家事8項目はチェックで選び、休日・家事の頻度・1日に使える時間・時間帯も候補から選ぶ。数値の手入力は要求しない。

- 1日に使える時間：平日・休日それぞれ15分／30分／60分／上限なし。既存動作を保つため初期選択は上限なし。
- 平日の時間帯：18〜20時／19〜21時／20〜22時。初期選択は利用者指定の19〜21時。
- 休日の時間帯：9〜12時／9〜19時／13〜18時。初期選択は9〜19時。
- 前回の実施・天気予報・ゴミ収集日は「必要なら設定」から任意で開く。開かず完了でき、戻っても選択は保持する。
- 詳細な時刻・上限の入力は通常の生活リズム設定で変更できる。通知許可は初回表示時には求めない。

最初の画面は8項目すべてと「次へ」が一画面に収まることをiPhone 17相当のライト／ダークで確認。生活リズムは一度のスクロールで下の時間帯と任意設定へ進め、確定操作は下部に残る。

設定と時間帯・時間上限は既存の所有者トランザクション内でまとめて確定する。保存失敗時のロールバック、保存後の表示更新失敗時に再初期化しないことを実SQLiteで検査した。シミュレーターでも平日30分・19〜21時が保存されたことを読み取りで照合した。

## 確認結果と既存の失敗

- lint・型検査・Release用iOS JavaScriptの書き出しとHermes変換を実施。
- 初回・下書き・説明対応先・分類保存の新しい検査15件、カレンダー検索／収集日／月次指定等34件、変更後の入力・権限・配線に合わせた検査17件、一人一端末の2件は通過。追加で実行した既存の機能契約／モバイルUI／ヘルプ・通知・Google設定等68件も通過。重複を含む実行単位なので合計を独立した不具合件数にしない。
- 登録検査は691機能契約と118 Cloud回帰検査の配線を確認。Cloudエミュレーターと実サービスの再検査を行ったという意味ではない。
- 診断用に広く実行した時点では4240件中4153通過・87失敗。今回と関係する旧UI期待・入力fixture等16件は修正後の対象検査で通過を確認した。全体を再実行して全件合格したとはしていない。
- 元の保存済みソースを別ディレクトリに展開し、失敗した対象モジュールを再実行したところ68件が同様に失敗。ホームの別1件も元ソースと現ソースで同じ `1 !== 800` を確認した。この失敗を処理時間の問題とは扱わない。
- 残る互換性契約2件／`npm test` の事前ゲートは、作業開始前から共有スケジューラーの実ソースと登録ハッシュが不一致。登録値 `8dc6858d…` に対し実ソースは `34aa1698…`。今回の前後ですべての署名対象ソースが同一であることを照合した。ハッシュや版だけを書き換えて通過させていない。
- 比較用の元ソースZIPは `src/tests/docs` を収録し、scripts・serverは含まない。比較実行時に参照したserverは今回変更していない現チェックアウトのもの。この境界を含め、実サービスや全体の健全性を証明したとは扱わない。
