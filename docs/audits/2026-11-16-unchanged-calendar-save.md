# 内容を変えない予定保存の通信抑制

Google同期済みの個人予定を編集画面で開き、そのまま保存すると、本文が同じでもrevisionが増え、次の通常同期がカレンダーと予定を再取得していた。両OSの実TSX・SQLiteと模擬Google portで、修正前はSQL書込1回・追加読取2回、Googleへの内容書込0回を確認した。

正規化した本文が同じ場合、系列と既存の個別回のrevision・予定書込・予定変更通知・家事計画キャッシュの無効化を省く。権限・系列と個別回の競合・日付の検証は同値判定より先に行う。初めての個別設定、取り消した回の復元、本人誕生日の復元は引き続き保存する。

予定本文を変えなくても、通知設定の差分と提出した下書きの削除は同じtransactionで保存する。別画面の新しい入力と共有用の下書きは保持し、保存後に必要な通知だけを出す。共有の署名処理、繰り返しの未来分割、Googleの受信・再試行・予定名省略の設計は変更しない。

## 検査

- 新しい登録回帰は7件。旧実装では4件が意図した差で失敗し、変更後は7件とも成功。
- 関連10ファイル172件とlint・型検査が成功。独立レビューの新回帰と未来分割20件も成功。重複するため合算しない。
- 同値保存はrevision・SQL書込・Google同期需要を増やさず、実際に本文を変えると通常のGoogle更新を行う。
- 競合・読取専用権限・通知と下書きのrollback・取消復元・初回個別回・本人誕生日復元を検査。
- detached個別回のmarkerと投影維持・同値保存・再取消は、追加の私的SQLite検査でも確認した。登録回帰と実機検証の代替には数えない。

実装前に変更案と不変条件を文章化し、評価後131秒以上を置いてから実装した。追加依存・スキーマ変更はない。使用する`runAsync().changes`は[Expo SDK 58のSQLiteRunResult](https://docs.expo.dev/versions/v58.0.0/sdk/sqlite/#sqliterunresult)に照合した。

この記録を作成した時点では、修正後の実機導入・通信計測・mainへの反映はまだ行っていない。再開監査の後続観測へ結果を追記する。
