# 繰り返し家事の未完了整理（2026年11月8日）

利用者が承認したルールは、前回の実施後に最初に発生した未完了回へ、今日の実施を1件だけ記録するもの。同じ家事の途中の自動予定を複数の完了実績に変換しない。

## 実装

- 個人家事は既存の学習処理が未完了回を1件保持していたため、学習アルゴリズムや参照数を変更していない。実SQLiteで、14日周期を30日放置しても最初の未完了ID・当時の実施期間が保持され、実際の完了日が1件だけ保存されることを回帰検査に追加した。
- 共有家事は同じ家事・設定バージョン・実施対象者の自動予定から最古の未完了回をホームへ表示する。現在の読取範囲より古い場合も、最後の実績から対象の周期番号を直接計算して取得する。放置日数分の全予定を再生成する処理は追加しない。
- 通常のチェック操作は最古の未完了回へ結び付ける。実施時刻・履歴は実際のものを保持し、その実施までに溜まった途中の自動回は派生状態として整理する。途中の回に完了イベントを作らず、元の署名付き設定・履歴も削除しない。取消しでは同じ入力から未完了状態を復元する。
- 明示的な日時指定、担当変更、期間延長、競合、承認待ちは別の義務として保持する。メンバー別の家事や、名前だけが同じ別家事も合併しない。共通周期の基準日や今後の周期枠は変更しない。
- 学習には実際の実施日同士の間隔を使う。1回の遅延だけで周期を確定せず、既存の最小実績数・参照数8/6/4・重み・期間内の学習停止を維持する。採用済み仕様どおり、共有共通周期は学習対象にしていない。
- 共有の履歴圧縮後も、既存の検証済み最終実績を使って整理済みの自動回の復活を防ぐ。履歴証明書や権限検査は緩和しない。
- Google Tasksの対象IDは維持し、古い未完了回の完了・取消しも投影する。途中の整理済み回に偽のGoogle完了日時を付けない。
- 変更前に保存された起動表示は新しい未完了回の分類を持たないため、キャッシュ形式を更新して一度だけ読み直す。古い表示から新しい回へ誤ったチェック操作を予約することを防ぐ。保存データや鍵を削除する処理ではない。

共有Schedulerは `liflow-shared-2-draft-52`、本人向け推奨は `liflow-personal-3` に更新した。正式な共有計算は本人のGoogle Calendar情報を参照しない。
