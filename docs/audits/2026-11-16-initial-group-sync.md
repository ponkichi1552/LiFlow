# 別端末で初回復元するときの地域エラー

## 観測と実装前の判断

検証用アカウントCでiPadへログインした際、利用者から地域の確認・変更を求めるエラーが報告された。画面を開き直すと、地域を変更せず同期できた。iPhoneとiPadの端末内記録は、同じ利用者・グループ・承認済み名簿の版2に収束し、同じ本人の2台が含まれていた。

原因の経路を確認し、2分以上検討して変更案を文章化した。端末の参加承認と鍵の受領は、家事・地域などの初回データ受信より先に終わる。その時点で表示先を保存しようとすると、予定の概要がまだ地域を取得できず、地域設定のエラーを返していた。

地域の検証を弱めたり、仮の地域を保存したりせず、表示先の確定順序を直す。承認済みのv2グループで初回同期の成功記録がない場合だけ、既存の同期処理で必要な初回受信を行う。検証済みの概要が読めてから表示先を確定する。同時の要求は一つにまとめ、受信が途中なら既存の変更通知・再試行につなげる。周期的な取得は追加しない。

## 変更と検証

- 初回データを待つ間は「復元中」とし、地域変更を促す誤ったエラーを表示しない。
- 通常の取得失敗、既に同期済みの設定エラー、アカウント・権限の変化は引き続き拒否・表示する。
- 参加承認だけでは表示先を確定せず、受信・概要の検証・アカウント再確認を終えてから保存する。
- 同時の初回表示では受信を一回にまとめ、既に表示先として保存されたグループや正常な概要には追加の同期要求を出さない。

修正前に5件の回帰が失敗し、修正後に共有の復元・表示・同一アカウントの端末復元を含む関連54件が通過した。型検査も通過した。テスト用のネイティブ境界からは、新しい純粋な準備処理を実際に読み込み、置き換えた成功結果で検査を省略していない。

この修正版を含む全体検査は、iOS・Androidともに4,484件、Cloud Emulatorは173件が通過した。lint・型検査・機能契約・計画処理の版検査も通過した。

同じ修正版の署名済みReleaseをiPhone・iPadへ上書き導入した。導入前後のSQLiteファイルは、iPhoneが92件、iPadが9件とも一致した。利用者が両端末を開き、iPadでも検証用アカウントCのグループを表示できることを確認した。これは受信済みグループの再開と認証の保持の確認であり、新しい端末で初回受信の遅れを再現した通過記録ではない。初回受信の実機再確認は別途記録する。

その後、同じソースのAndroid Releaseをデータを消さずに上書き導入した。検証用アカウントDが専用グループへ参加を申請し、iPhoneの管理側と確認番号が一致した。参加後は、地域の再入力やアプリの再起動をせずに2人のグループ設定と共有カレンダーを表示し、先にiPhoneで作成した検証予定の名前・日付・09:00の開始時刻をAndroidでも確認した。初回受信の通常経路の実機確認であり、意図的に初回パケットを遅延させた試験ではない。Androidの元の個人家事8件も保持していた。

iPhoneとiPadの読み取り専用コピーは、署名付きの受理済み84操作、保留0、同じ検証予定の署名・本文に一致した。端末の見た目の確認だけで保存内容の一致を推定していない。Androidの保存DBは読めないため、Androidは実画面による受信確認として区別する。
