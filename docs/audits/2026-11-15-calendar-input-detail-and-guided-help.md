# カレンダーの日時入力・月の詳しさ・画面上の案内

## 実装前の指示整理

19:20の追加指示を受け、実装前に2分以上かけて既存の入力・ドラッグ・月の行高・ヘルプの配置を検討した。変更は、月カレンダーの縦線から独立した操作枠の仕切り、予定名からの日時入力、月表示の詳しさ、実際の画面を使うヘルプに限定する。ホームの操作や家事完了、同期の仕組みは変えない。利用者は「来週」等の解釈を月曜始まりと指定した。

## 仮配置と自己評価

```text
右下   [ 検索  |  ？ ]       仕切りは上下を短くする

予定名 [来週の火曜日18時から友達と食事]
開始   [次の週の火曜日] [18:00]
終了   [同じ日]         [既存の所要時間を保った終了時刻]

既存の表示選択
1日 / 2日 / リスト
月表示の詳しさ
すっきり / 標準 / 詳しく

実際のカレンダーをそのまま背景にするヘルプ
  対象以外を暗くし、実際の予定や＋などを囲む
      ↑ 矢印
  [1/4 予定を長押しして移動
   月は日付だけ、1日・2日は日時を移動。
   閉じる                       次へ]
```

- 仕切りは操作枠の中央だけに描く。上下の枠線と接続しない。囲いをカレンダーの罫線から区別でき、既存の検索・ヘルプの位置と操作幅を保てる。
- 日時はAI・ネットワークなしで決められた表現を解析する。新規の通常予定だけを対象にし、既存予定の編集・誕生日・選択済み家事へ勝手に適用しない。予定名は削らず、そのまま保存する。
- 相対日は入力時のカレンダー地域の今日を基準に固定する。今日・明日・明後日、来週／再来週と曜日、N日／週間／か月／年後、年月日・月日、24時間表記・午前午後・半・終日に対応する。週は月曜始まり。「来月」「1年後」は同日、存在しない日は月末にする。無効な日付、複数の競合する指定、曖昧な日時は推測で確定しない。
- 時刻だけなら選択中の日付を保つ。開始を移す場合は現在の予定時間を保つ。終了時刻も明記された場合は終了へ反映し、日付をまたぐ指定を扱う。入力途中の不完全な数値で不正な日時を作らない。手で変更した日時は以後そちらを優先する。解析語を消した場合は、手動で変えていない自動入力分だけ元に戻す。
- 月の詳しさは既存の表示メニューに置き、ヘッダーや画面下へボタンを追加しない。「すっきり」は予定名1行・時刻なし、「標準」は現状の空きに応じた名前・時刻、「詳しく」はすべての週を同じ高さで広げ、表示できる件数を増やす。家事件数・ゴミ収集日・+Nを先に確保し、特定の週だけ伸ばさない。端末内の表示設定として保持し、共有へ送らない。
- ヘルプは実画面に重ねる案内へ置き換える。通常予定が実際に見えていればそれを囲み、なければカレンダーの領域を使って「追加した予定を長押し」と案内する。架空の予定を本物に見せたり、検証用予定をユーザーの予定に作ったりしない。＋、表示選択、検索を実際の位置で示す。閉じる／完了／OSの戻るで日付・形式・スクロールを維持する。
- ネイティブの測定結果から囲い・矢印・説明位置を決める。画面幅・高さ・向きに合わせ、説明カードを画面外へ出さない。背後の操作を止め、案内中に予定を保存・移動しない。初回だけ自動表示する既読の仕組みを保つ。

## 検証方針

純粋な日時解析の暦・月末・閏年・週境界・全角・誤認識・手動修正を検査する。入力した直後のフォームと保存先の実値、複製・編集・家事との境界を両OSで確認する。月の全件数と余白計算、設定保存の重複なし、初回案内・再表示・閉じる・実座標・画面外へのはみ出しを回帰対象にする。見た目そのものは既存のシミュレーター1台で確認し、物理iPhoneは使わない。

## 実画面での位置の再評価

初回フォーカス直後は、UIKitの表示完了前のヘッダー位置と、仮想リストが予定を描画する前の状態を測定してしまうことを確認した。固定のSafe Area補正や待ち時間による推測は使わない。案内のネイティブ表示完了で測り直し、案内が開いている間だけ、予定のマウント・カレンダーのレイアウト・スクロールの通知をまとめて再測定する。閉じると購読と未完了の測定を解除する。アイドル時のポーリング・通信は追加しない。
