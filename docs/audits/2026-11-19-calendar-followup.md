# カレンダーの追加監査

月・日・週・年・リスト表示と編集導線、日付・繰り返し・保存、SQLite・Google・共有・通知を6.2-astraのサブエージェント3つで調査した。以下はコード上の原因と再現条件を確認できた項目。発見件数を停止条件にせず、該当経路を一巡した。

## 優先度が高い不具合

| 事象 | 再現条件と原因 | 修正範囲 |
| --- | --- | --- |
| 繰り返し全体をドラッグすると、ドロップした日と違う日に保存される | 毎月30日の4月30日を5月1日に移して「繰り返し全体」を選ぶと、移動先に予定がない。第2火曜の時刻だけを動かして、作成時の基準日が木曜なら曜日まで変わる。`src/features/calendar/direct-actions.ts` | 元ルールとドロップした回から変更を作り、移動先にその回が存在することを保存前に検査する。移動先に合わせられない範囲は「この予定だけ」を選べるようにする。 |
| 保存後の下書き整理に失敗すると、再試行で予定が複製される | 新規予定のDB保存は成功し、下書き削除だけが1回失敗する条件で「保存」を再タップすると2件になる。`src/features/calendar/calendar-editor.tsx` と `src/platform/storage/calendar-events.ts` | 保存が確定した予定の識別子を保持する。再試行は下書き整理だけを行う。 |
| 共有家事の日付変更が別の日を選び、開始・終了時刻を消せる | 2・3・7日表示で選択日が月曜のまま火曜の時刻付き家事をタップすると、月曜の日付だけで変更フォームが開く。`src/features/sharing/v2-ui/calendar.tsx`、`group-screen.tsx`、`date-form.tsx` | タップした日の回をフォームへ渡す。日付だけの変更では時刻と所要時間を保持する。 |
| Googleの繰り返し変更を取得できないと、以前の予定が表示から消える | 対応済みの繰り返しルールが変わり、個別回の取得が503を返すと、表示していた旧回が先に削除される。`src/features/calendar/personal-google-sync.ts` | 新しい回の取得と保存が揃うまで前回の表示を保持する。揃った時点でまとめて置き換える。 |
| Googleから1年以上の終日予定が届くと、他の予定の同期まで止まる | 約2年の終日予定を同じ受信バッチに入れると、単発予定2件と送信待ち予定も処理されず、再試行で同じ位置に止まる。`src/features/calendar/personal-google-sync.ts` と `src/platform/storage/personal-google-store.ts` | 長期の予定を個別に保持・表示し、同じバッチの別予定と送信待ちを進める。 |
| Googleの全件再取得後も、取り消された個別変更が残る | 410後の全件取得に旧個別変更が含まれず、元の繰り返しだけが届いても移動済みの日に残る。`src/features/calendar/personal-google-sync.ts` | 最終ページまで取得した後に個別変更も照合し、ローカル未送信の変更は競合として扱う。 |

## ほかに再現した不具合

| 事象 | 再現条件と原因 | 修正範囲 |
| --- | --- | --- |
| カレンダーのリストで、予定がない日が大きい行のままになる | 個人・共有の両画面が収集日描画関数を毎回渡すため、収集なしの日も短い「予定なし」行にならない。`src/features/calendar/planner-calendar.tsx` | 収集の有無を日付単位で判定して短い行の条件に使う。 |
| 表示中の個別変更が検索に出ない | 繰り返しルールの変更後に残した個別回をリネームすると、画面には出るが名前で検索できない。`src/features/calendar/search.ts` | 採用済みの個別回を表示と同じ条件で検索する。 |
| 検索結果が、予定のない日に飛ぶ | 全回を取り消した繰り返しと、次の回まで8年超ある繰り返しの検索で、実際の次の回の代わりに古い基準日に飛ぶ。`src/features/calendar/search.ts` | 周期に沿って次の回を求め、表示できる実際の回を確認してから結果を作る。 |
| 同じ日にある別の回も検索先として選択表示する | 翌日の別の回と同じ日に移動した予定を検索すると、別の回も同時に色が付く。`src/features/calendar/planner-calendar.tsx` | 予定IDと元の回の日付を検索先に保持し、開いた回にだけ選択を付ける。 |
| 別のタイムゾーンの予定を編集すると、元の表示日から移動する | 東京で11月19日に見えるニューヨーク11月18日23時の予定を開き、そのまま保存すると11月18日の表示へ移動する。`src/features/calendar/calendar-editor.tsx` と `planner-calendar.tsx` | 画面のタイムゾーンと、開いた個別回を保存後の表示位置に使う。 |
| 見ている年とは違う年に予定を追加する | 年表示を2028年まで進めて「＋」を押すと、2026年の日付で編集が始まる。`src/features/calendar/planner-calendar.tsx` | 表示している年を選択中の月日と組み合わせる。 |
| 同じ個人家事の複数回を共有カレンダーに表示できない | 時刻を持つ回が複数日にあると、家事IDで重複を除くため最後の1回だけ残る。`src/features/sharing/v2-ui/calendar.tsx` | 家事IDに加え、予定の回の識別子を使う。 |
| 夏時間終了をまたぐ予定が時間軸に表示されない | 現地の01:50から時計が戻って01:10になる実時間20分の予定は、表示終了時刻が表示開始時刻より前として除外される。`src/features/calendar/layout.ts` | 実際の経過時間で表示範囲を構成する。 |
| 日付をまたぐ予定の深夜部分が、最初の表示に入らない | 23時から1時までの予定がある翌日を開くと、深夜の表示位置ではなく23時へスクロールする。`src/features/calendar/planner-calendar.tsx` | 表示日にかかる実際の開始位置を初期スクロールに使う。 |
| 長押しを離すだけで、元の分から時刻が変わる | 09:02の予定を0.25ピクセル動かして離すと09:00で保存される。読み上げの「5分後」は09:05になる。`src/features/calendar/direct-actions.ts` | 予定の時刻を丸めず、指で動かした分だけを5分刻みにする。読み上げ操作は指定された分数で移動する。 |
| 個人の繰り返し全体を変更した直後に個別回の通知が消える | SQLite上では日曜から月曜に通知設定のキーが移るが、通知設定の更新を購読側へ伝えない。`src/platform/storage/calendar-events.ts` | 通知キーの移動についても、保存後に更新を通知する。 |
| 共有の繰り返し全体を変更すると、その人の個別回の通知が消える | 共有予定は翌日に移るが、その人だけの通知設定は旧日付に残る。画面を開き直しても元に戻らない。`src/features/sharing/v2-ui/use-group-calendar.tsx` と `v2/calendar-actions.ts` | 共有の保存確認後、個人の通知キーを同じ移動に合わせる。再試行で重複させない。 |
| 共有グループの読み込み中、すでに設定した有効な通知が解除される | アプリ起動直後の復元中や、メンバー確認済みで表示データの準備中の場合、共有予定が0件として通知を照合する。`src/features/calendar/calendar-notification-bridge.tsx` | 同じグループの復元中は既存通知を保持する。アカウントの切り替えや権限の失効時は失効した範囲だけ解除する。 |
| 夏時間の切り替えで存在しない時刻を、今後の予定として修正しにくい | 02:30が存在しない回を有効な03:20へ直しても、「今後の予定すべて」では変更前の02:30を先に検査して失敗する。`src/domain/calendar/future-series.ts` | 元の繰り返し回の日付を基準にし、実際に保存する修正後の日時を検査する。 |
| 夏時間の切り替えで「前日」の通知日がずれる | 前日を24時間前で計算するため、地域と日付によって前々日または当日に届く。深夜0時が存在しない日には、終日予定の開始通知が作られない。`src/features/calendar/calendar-notifications.ts` | 地域の日付を1日前へ進め、終日はその日の実際の開始境界を使う。 |
| 予定名に書いた除外条件や人名を日時として読み取る | 「11:00以降に集合」を11時に設定し、「明日の10時以外は空き」で除外した10時に設定する。「明日香さん」で日付が翌日になり、「午後2時から4時」が翌朝4時までになる。`src/features/calendar/title-datetime.ts` | 表記に共通の除外判定、語の境界、午前・午後の継承を扱う。 |
| 別のGoogleアカウント由来のカレンダー名が分類に残る | Googleアカウントを切り替えると、旧予定は消えるが旧カレンダー名が分類一覧に残る。`src/platform/storage/personal-google-store.ts` と `calendar-events.ts` | Google由来の分類を接続アカウント・アクセス範囲で表示する。自作の分類と保存済み予定は維持する。 |
| 保存済みの過去予定が多いと、今日のカレンダーが読めなくなる | 過去の予定が10,001件あると、現在月の予定も読み込み上限で取得できない。`src/platform/storage/calendar-event-rows.ts` | 表示範囲を使って予定・移動済みの個別変更を読む。過去のデータは保存する。 |
| Googleの初回取得で同じ通信を繰り返す | 差分トークンなしの取得に410が返ると、1回の同期で同一の要求を74回送る。`src/features/calendar/personal-google-sync.ts` | 差分から全件への切り替えを1回に制限し、全件取得でも失敗したら通常の再試行に戻す。 |

## 待ち時間を減らせる箇所

| 箇所 | 確認結果 | 修正範囲 |
| --- | --- | --- |
| Googleからの初回取り込みが保存バッチごとに終了する | Google応答を即座に返す1,000件の試験では、旧処理が31回に分かれ、カレンダー一覧を31回取得した。標準の再試行待ちを合計すると2時間17分30秒。`src/features/calendar/personal-google-sync.ts` と `src/features/google-sync/demand-worker.ts` | 今回対応済み。受信時間・通信の予算内で25件ずつ保存を続ける。同じ試験では1回で完了し、一覧の取得も1回。 |
| 先の月へ飛ぶと、途中の年までGoogleに要求する | 2199年1月と現在の取得範囲の間を一つに連結すると、未対応の繰り返しごとに62,736日分の範囲になる。`src/platform/storage/personal-google-ranges.ts` | 離れた期間は範囲を分けて保持し、表示中の範囲を先に要求する。 |
| 予定の通知計算で、各回が通知設定を最初から探す | 毎日の繰り返し30本で55,830回、60本で223,260回通知設定を確認し、どちらも残る通知は32件。`src/features/calendar/calendar-notifications.ts` と `reminder-preferences.ts` | 通知設定を識別子で索引化し、時刻順を保って必要な件数まで計算する。 |
| 繰り返し全体の変更で、個別回ごとに基準日からの計算を繰り返す | 古い毎月の繰り返しに144件の個別変更があると、開始日を30,524回参照した。ホスト計測で約60 ms。`src/domain/calendar/exception-slots.ts` | 個別回を日付順に処理し、同じ繰り返しの探索結果を保存・通知の移行で再利用する。 |
| 検索を開く前に家事の検索候補を組み立てる | 730日・2,920件の合成データでは、端末外の計測で中央値26.6 ms。`src/app/(tabs)/explore.tsx` | 検索を開いたときに準備し、同じ家事の範囲を再利用する。 |
| 表示する予定カードごとに履歴全件から編集の可否を探す | 予定1万件、個別回1万件でカード120件を調べると、ID照合が約239万回。`src/features/calendar/private-event-projection.ts` | 表示用の編集可否を、確定したスナップショットごとに索引化する。保存時の権限確認は保持する。 |
| 通信とSQLite保存の間で、同じ接続状態を何度も読む | 更新のない個人カレンダー1件の模擬同期でHTTP2回に対してアカウント確認37回、設定のSQLite読込28回。`src/features/calendar/personal-google-sync.ts` | 実機で確認ごとの時間を測り、アカウントと保存先を検証する境界の重複を減らす。 |
| 更新のない旧方式の共有同期で空の履歴を追加取得する | サーバーで最新位置と現在位置が一致した後も、空の履歴クエリを2回実行する。`src/features/sharing/synchronizer.ts` と `src/platform/sharing/firestore-cloud.ts` | 最新位置と所属の検証を保ち、一致時に空の取得結果を返す。 |
