# カレンダーの家事操作・日付見出しの設計確認

## 指示を操作へ対応させる

| 対象 | 押した結果・表示 |
| --- | --- |
| ホームの家事名 | 個人・共有とも家事の説明を開く |
| カレンダーの個人家事の未完了行 | 右端に枠付きのカレンダーマークを表示し、その回だけの日付を変更するシートを開く |
| 家事のチェック | 説明・日付変更を起こさず、完了状態を変更する |
| 1日・2日の本文を左右にスワイプ | それぞれ1日・2日ずつ切り替え、見ていた時刻を保つ |
| 縦スクロール・予定の長押し移動 | 日付切り替えを発生させない |
| 誕生日 | 日付と同じ行に表示し、既存の編集操作を保つ |

## 仮配置

カレンダーの個人家事は実施日の調整に使う。説明の入口と独立した日付変更ボタンを重ねず、チェック以外を一つの行操作にする。右端の枠付きカレンダーマークを日付選択の目印にし、ホームの説明を開く矢印と見分ける。ホームの動作は変更しない。

```text
           11月14日 土  🎂 誕生日
家事 3件・約40分                    ⌃
───────────────────────────────────
□  浴室の清掃                   ▦
───────────────────────────────────
□  トイレの清掃                 ▦
```

2日表示でも同じ配置を使い、ボタンのために2段へ増やさない。

```text
11月14日 土 🎂 誕生日 │ 11月15日 日
家事 3件         ⌃ │ 家事 2件       ⌃
───────────────────┼─────────────────
□ 浴室の清掃   ▦  │ □ 部屋の清掃  ▦
───────────────────┼─────────────────
```

## 利用者からどう見えるかの自己評価

以下は実際の利用者の発言ではなく、実画面で検証する仮説。

- カレンダー内に説明の操作を加えると、実施日調整という目的へ不要な選択を増やすため不採用。説明はホーム・家事一覧で参照する。
- ホームは矢印、日付編集できるカレンダーの行はカレンダーマークにし、同じ見た目に違う動作を隠さない。
- チェックと行本体の領域を分け、日付の調整で完了を記録しない。
- 独立ボタンの反復と2段の配置をやめ、家事名の幅と時間軸の領域を保つ。通常の家事名が1行に収まり、長い名前は2行まで表示し、収まらない部分を省略する。全文は同じ日付選択シートで確認できるか実画面で確認する。
- 誕生日を日付の横に置くことで、見出しの不要な2段化を避ける。長い誕生日名でも日付・未取得表示を消さず、読み上げに全文を残す。
- 左右のスワイプは日付の移動、縦方向は時刻の閲覧、長押しは予定の移動として競合を確認する。

## 今回の見直し

初案では家事名に日付変更を割り当て、ホームにも波及させた。修正案でも説明と日付変更を並べて操作を増やしてしまった。カレンダーでは実施日調整を優先し、説明への入口を重ねない。ホームから説明を開く動作を保ち、カレンダー側の表示で操作の違いを明示する。

### 日付シートの仮配置

```text
閉じる       実施日を変更       保存
浴室の清掃
      2026年     11月      14日
      年・月・日を直接選ぶホイール
```

iOS標準の月カレンダーは年月選択と月移動に別々の矢印があり、この用途では見分けにくい。既存の日付入力と同じホイールへそろえる。選択するだけでは保存せず、保存・閉じるの位置と競合チェックを保つ。大きな月カレンダーや専用の月移動操作を加えず、必要な高さだけのシートにする。

この記録は初案の実装後に整理したもの。以後の追加修正は、先に指示・仮配置・評価を記録し、2分以上の検討を行ったうえで実施する。時間の経過だけを設計確認の代わりにしない。

## 検証

### 横スワイプの追加確認・修正案

- 21:52の実画面確認では、縦のドラッグは時間軸をスクロールできたが、横のドラッグで日付が変わらなかった。操作ハーネスの成功だけではネイティブの競合を確認できていなかった。
- 仮の処理順序は「横方向の判定を待つ → 横なら日付を変更／縦なら通常のスクロールへ渡す」。画面配置とタップ操作は変更しない。
- スクロール部分を同じネイティブのジェスチャー判定へ参加させ、横方向かどうかが決まる前にスクロールが操作を奪わないようにする。
- 自己評価：本文からの横スワイプを追加しても、縦スクロール・タップ・長押し移動の意味を変えないことが必須。長押し移動中には日付切り替えを止め、終了後は通常の操作へ戻す。
- 実画面で左右両方向・1日／2日・縦スクロールを確認してから完了とする。
- 共通ドラッグツールによる直接入力で、1日表示の11/14→11/15→11/14、2日表示の11/14・15→11/16・17→11/14・15は確認できた。一方、この時点では縦方向のスクロールが待ち関係に止められていた。下記の最終確認では同時認識へ修正した版を使った。
- 追加修正案：横スワイプとネイティブの縦スクロールは同時に認識できる関係にし、横に動いた場合だけ日付を切り替える。ライブラリーが提供するネイティブ対応のリスト・スクロール部品へ接続し、長押し移動中の停止条件は維持する。

### 時刻付き個人家事の操作経路の最終整理（実装前）

- 指示：カレンダーでは家事説明への不要な寄り道を増やさず、家事の日時を調整できるようにする。ホームは説明を開く。
- 発見：今回の途中修正で、時間軸に描く個人家事のタップを、従来の日付変更から説明へ変えていた。未完了行だけを直してもカレンダー内の操作が食い違う。
- 仮動作：時間軸の個人家事をタップ → 同じ「実施日を変更」シート → 日付を選択 → 保存。時刻の直接移動は既存の長押し移動を使う。追加のボタンや表示行は増やさない。
- 評価：カレンダーでは予定の日時を扱い、ホームでは手順を読む。保存先は元の回のIDに固定し、日付以外の時刻・長さ・周期・実施履歴を変えない。共有家事の担当・権限の経路は変更しない。
- 検査：個人カレンダー単独と共有表示内の個人家事の両方について、時刻付きブロックが元の個人の回の日付シートへ到達することを操作で確かめる。説明のルートへ戻らないことを回帰検査へ残す。


### 長い家事名を前提にした再評価（実装前）

- 指示：短い名前だけを並べた画面で判断せず、長い家事名が読める配置にする。2日表示でも名前のための幅を確保する。
- 問題：各行に「日付」を繰り返したうえで名前を2行に制限していた。長い名前を隠し、日付の操作が名前の幅を圧迫している。短い3件だけの目視確認では不十分だった。
- 仮配置：`□ 家事名（必要な分だけ折り返す）  カレンダーマーク`。マークは既存の日付入力と同じものを使い、独立した操作ボタンの幅を確保せず、チェック以外の領域全体を同じ日付選択の操作とする。操作用の2段目は作らない。
- 長い例：`エアコン室内機のフィルター・吹き出し口・ルーバーの掃除`、`洗濯機の洗剤・柔軟剤投入口とゴムパッキンの汚れ落とし`。実画面で名前を最後まで表示でき、チェックとマークが重ならないことを確認する。
- 自己評価：行数を固定して隠す代わりに、その家事に必要な高さを使う。多い場合は既存の家事欄だけのスクロールを使い、日付見出しと時間軸の最低領域を残す。文字を縮めない。2日表示の細い列で長い名前が何行にもなる点は許容するが、別の操作行や説明を追加しない。
- 検証：短い名前・長い名前・1日・2日・明暗を、既存データを変えない独立したシミュレーター用データで確認する。表示の確認に加え、名前を読み上げる対象と日付変更の対象が一致し、チェックは独立して完了操作になることを検査する。


### 長い名前の仮案を実画面で棄却した理由・修正方針（実装前）

- 1日表示では長い名前が2行に収まったが、2日表示では1件が5行程度になり、家事欄が上限まで広がった。全文の折り返しだけでは一覧性を損なうため、この仮案は不採用。
- 最終方針：カレンダーマークで操作幅を抑え、家事名は最大2行まで自然に折り返す。収まらない末尾は省略を明示する。タップ先のシートは家事名を全文で表示する。操作用の2行目・説明への寄り道・文字の縮小は加えない。
- 評価：短い名前は1行のまま、長い名前も一覧の密度を大きく変えず見分けられる。全文を日付選択シートで確認する手間は残るが、実施日を変える既存の1回のタップと同じ入口で確認でき、別の説明ページや専用操作を増やさない。狭い2日表示で全文と短い行を両立できるという誤った仮定は置かない。
- 追加確認：長い名前の末尾がチェックやマークへ重ならないこと、シートに全文が出ること、家事欄の高さ上限と時間軸を保つことを確認する。


### 日付操作を押せる形へする再評価（実装前）

- 指示：カレンダーマークだけで押せると判断できるかを見直す。単なる装飾に見せない。
- 問題：青いマークだけでは、タップできる操作と状態表示を視覚的に区別しにくい。
- 仮配置：`□ 家事名（最大2行） [カレンダー]`。右端のマークに通常の補助操作と同じ白系の背景・枠線・角丸を付け、ボタンの形にする。文字説明は増やさない。
- 評価：大きな44幅の独立ボタンを増やすと家事名を再び圧迫するため、見える枠はチェックと釣り合う大きさにし、既存の行全体のタップ領域（高さ44以上）を使う。マークとの隙間も合わせて調整し、家事名の幅をほぼ維持する。見える枠の中だけしか押せない作りにはしない。
- 行を押す操作は今回の日付変更のまま。チェックは独立して完了操作を保つ。保存ボタンより強い塗りや、選択済みと誤認する水色の塗りは使わない。
- 確認：1日・2日、短い名前・長い名前、明暗で枠が見え、マーク・名前・チェックが重ならないことを実画面で再確認する。枠線の数値そのものを固定する自動検査は追加しない。


### 枠付き操作を含む行全体の再評価（実装前）

- 指摘された画面の問題：家事名を広く残そうとして名前とボタンの間隔をゼロにした結果、長い文字列が枠へ近付きすぎた。青い枠の反復も文字より強くなっている。個々のマークだけを直し、行全体の余白と強調度を評価できていなかった。
- 仮配置：`チェック領域 | 家事名の領域 | 余白 | 日付操作`。名前と日付操作の間には明確な余白を置く。日付操作は青い記号と通常の入力欄と同じ中立色の枠・白系背景にし、保存の強調と区別する。
- 名前は文字サイズを縮めず最大2行を保つ。長い日本語は自然な語の区切りを使う改行設定を確認し、全文は日付シートで表示する。短い名前を無理に1行へ収めるために隣接する操作へ接近させない。
- 評価：余白を確保すると2日表示の名前の表示量は少し減るが、文字と操作がぶつかる配置より読み取りやすい。長い名前の全文が狭い列へ入るという前提は置かず、通常の短い名前・最悪例・ボタンの存在を同じ画面で比較する。ボタンだけを派手に塗り、操作を分かりやすくしたと扱わない。
- 変更範囲：家事行の余白・日付操作の見た目・日本語の折り返しに限定する。チェック、今回だけの日付変更、ホームの説明、保存・周期・通知の処理は変更しない。

- 狭い列の追加評価：間隔だけを広げると6文字程度の通常名まで不要に折り返すため、補助ボタンの枠・記号を小さくし、一覧の内側の余白も整理して表示幅を確保する。名前との間隔は明確に残し、ボタンのタップ領域は行全体で保つ。文字の縮小・押せる範囲の縮小は行わない。
