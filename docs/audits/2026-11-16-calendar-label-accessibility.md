# 予定入力のラベルと文字拡大

## 観測・変更前の判断

Android実機の共有予定を開くと、「開始」「終了」が1文字ずつ改行し、「繰り返し」の最後の1文字も別行になった。端末設定は文字倍率1.15、1080×2520、density 420。端末設定や利用者の文字倍率は変更していない。

原因は、ラベルの文字サイズはOS設定に従って大きくなる一方、2文字の日付ラベルが幅36、4文字の項目ラベルが幅76に固定されていること。入力済みの日時や共有権限の問題ではない。

変更案：既存の余白と行構成を基準にし、左右で揃えるラベル列の必要幅を文字倍率にも追従させる。開始と終了、繰り返しと分類はそれぞれ同じ幅にする。文章の追加、文字倍率の制限、保存や編集権限の変更は行わない。

自己評価：日本語の単語が意図せず分割されることを防ぎ、項目と入力欄の関係を維持する。単に改行を禁止して文字を切り落とさず、列自体に必要な幅を確保する。通常倍率、実機の1.15倍、より大きな文字で、日付・時刻欄と干渉しないことも画面で確認する。見た目だけの変更のため、既存の全体検査を繰り返す代わりにlint・型検査と該当画面の確認を行う。

## 実装・確認

変更案の記録から164秒以上、原因・影響・列幅の関係を確認してから実装した。`useWindowDimensions().fontScale`にラベル列幅を追従させ、開始と終了、変更範囲と繰り返しと分類でそれぞれ同じ列幅を使う。通常倍率の基準値は維持する。

lint・型検査が通過し、AndroidとiOSのReleaseビルドが成功した。3実機へ上書き導入し、Apple 2端末は導入前後の保存ファイルがバイト単位で一致した。Androidはアプリの保存領域を消さず更新し、検証グループと既存8件の期限切れ家事を画面で再確認した。

Android実機の文字倍率1.15倍で新規の時刻付き予定を開き、「開始」「終了」「繰り返し」が途中で改行されず、日付・時刻欄と干渉しないことを確認した。iPhoneでも時刻付き・終日の編集を確認した。端末の文字設定は変更していない。より大きな文字倍率を含む全設定の確認完了は意味しない。

画面だけの変更として全体テストは再実行していない。前の4修正を含む4,484件×両OS・Cloud 173件の通過記録は、この表示調整後の全体実行とは分けて扱う。
