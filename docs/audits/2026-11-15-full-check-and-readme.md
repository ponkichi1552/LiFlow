# 全体検査とREADME更新 — 2026年11月15日

## 対象

利用者が承認した全体テスト、不具合修正、GitHubの正本更新に、READMEの書き直しと最新画面への差し替えを追加した。

作業開始時の `main` と `origin/main` は、どちらも `e5652cee6f28ee8a6d57111535566191472896b2`。既存の家事・カレンダー・設定・同期・PDF登録の変更を含む現在の作業コピーを対象とした。作業開始時の未コミット変更、未追跡ファイル、Git履歴は、リポジトリ外の非公開チェックポイントへ退避し、内容のSHA-256とGit bundleを検証した。

既存のローカル検査データ・退避用 `artifacts/` はGitHubへの追加対象にしない。実機iPhone、本番Firestoreのデータ、配備済みRules、ストア課金設定は変更しない。OpenAI実API検査は利用者の指示どおり保留した。

## 見つかった不具合と修正

### 時刻付き共有家事の対象メンバー

各自実施の共有家事を特定の参加者だけに設定しても、時刻の指定をグループ全員分生成していた。設定対象外のメンバーに対する操作が受信権限で拒否され、登録全体が失敗する。

設定された担当方式と参加者の集合から、時刻指定の対象を決めるように修正した。全員対象の場合の保存済み対象者リストも尊重する。

`timed per-member chore creation designates only its configured participants and converges without extra subjects` を追加。修正前の権限拒否を再現し、修正後は指定した本人分だけが作られること、署名付きの別端末へ一致して反映されること、余分な実施対象を増やさないことを検査した。

### 共有家事のカレンダー操作

個人家事では行を押すと今回の日付変更を開くが、共有家事のカレンダーには既存の日時変更コールバックが渡っていなかった。共有行・時刻ブロックだけが説明・実施記録の画面へ進む状態だった。

既存の共有日時変更画面へ、押した実施回・本人分・元の基準日を渡す。個人と同じカレンダーの印を使い、操作を追加のボタンに分けない。既存の権限・古い設定の拒否・申請承認・競合確認は変更しない。

`shared calendar rows and timed chores open the captured occurrence date editor without changing home guides or writing` を両OSで追加。修正前の欠落を再現し、日付のみの行・時刻付きブロックの遷移先と識別子、開くだけでは保存しないこと、ホームの説明と独立した完了チェックを維持することを検査した。

### カレンダーモジュールの参照

`shared-events.ts` の純粋なカレンダー検証関数の参照を、同じドメイン実装で使う明示的な `.ts` 参照へ統一した。Node側で共有投影・同期の検査を読み込めない問題を修正し、ネイティブ側の投影にも同じ検証を使う。

### 依存関係

- `node-forge` を1.4.3へ更新。Expoの2つの利用元が同じ修正版を参照すること、既存の署名・証明書検査を維持した。
- 家電APIの `fast-xml-parser` を5.12.1へ更新し、関連するパーサー依存もロックファイルへ反映した。

参照した公式アドバイザリ：[node-forge](https://github.com/advisories/GHSA-w4xr-hqv8-ch44)、[fast-xml-parser](https://github.com/advisories/GHSA-474x-hrwr-fgx4)。

## テストの更新方針

既に承認された利用方法に合わせ、以前の画面や文言を前提にしていた検査を更新した。

- カレンダーの完了チェックを前提にした操作を、ホームでの完了とカレンダーへの表示反映へ変更。
- 設定を離れる際に無効な入力・保存失敗で移動を止める期待を、保存済みデータを保持して未保存分だけ破棄する期待へ変更。
- 画面に留まっている間の古い権限・競合・失敗下書きの検査は、背景移行による保存を使って保持。
- 繰り返し全体の編集で、個別変更済みの予定を保つ期待へ更新。
- 新カタログの共有初期化件数を、利用可能な非収集項目から求める。初期化件数と暗号化送信件数の一致は引き続き検査。
- PDFのみの家電登録、文書形式の説明、現在の画面名に合わせて操作経路を更新。
- 色・枠線・内部の配置を固定していた部分を整理し、日付選択・収集種類・件数・保存先の検査を維持。
- 画面ハーネスで、明示的に注入した同一モジュールの別名参照と相対参照を対応させた。実際の権限・SQLite・同期処理は検査対象に残した。
- 遅延同期の終了を固定回数の描画待ちで推測していた検査を、実際に起動した同期Promiseの完了待ちへ変更。保存済み状態・送信件数・入力ロックの検査は維持。

契約やCloudの検査をまとめて削除・スキップして成功させる変更はしていない。697機能契約と118必須Cloud参照の登録を検査した。

## 今回観測した画面動作と限界

- 初回の家事選択から、生活リズムの候補を使って設定を完了。
- ホームのチェックで追加画面を開かずに完了し、再起動後にも実施が残る。
- ホームの家事名から説明を開き、戻るとホームへ復帰。
- 家事一覧を分類から展開し、名前を確認。
- 月表示に予定名・時刻・家事件数と日本の祝日色が表示される。
- 日表示の家事には完了チェックがなく、日付変更の印から対象家事のシートを開く。
- シートを保存せず閉じると、元の選択日と家事へ戻る。
- 家電登録はPDF添付だけを入口にし、メーカー・製品名・型番の入力欄を出さない。

Device Hub経由のスクロール・ドラッグ入力では移動を再現できない操作があり、今回その操作の滑らかさを新しい実画面で合格とは扱わない。今回の2つの修正のうち、共有の担当者集合と共有日時変更の正確な回の識別は、署名・SQLite・遷移を含む自動回帰で検査した。ログイン済み実機・本番Google・本番グループで再検査した結果ではない。

実購入、Apple認証の実サービス設定、本番端末証明、新しいPDF入力方式でのOpenAI実APIは、引き続き別の確認が必要。スクリーンショットやNodeの画面ハーネスの成功を、それらの実サービス検査の代用にはしない。
